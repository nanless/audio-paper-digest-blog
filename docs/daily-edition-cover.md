# 每日论文选读封面

网站正常构建 `npm run build` 会先运行 `scripts/select-edition-feature.js`，再由 Hugo 生成网页。新一期日更推送到 `main` 后，既有 Pages 流程会自动完成选择和展示，不需要另建定时任务或手填日期。

## 选择范围

选择只使用最新一期完整「论文列表」中的正式成员。最新一期必须是唯一的日期批次：页面不是会议页，`date` 只写到日，同一天只有一个批次；否则不做自动选择。成员列表必须恰好有一个 `## 论文列表` 小节，每个 `###` 成员只链接到本站一篇论文，不能重复；描述或正文至少有一处“共分析 N 篇”，各处数字必须与成员数一致。候选论文还须是同一日期、非草稿的论文页，arXiv 编号、版本编号、abs 地址和 0–10 分评分齐全。

先优先选择方法总览、架构、流程等关键图，再按本站论文评分排序。方法图由图片替代文字和就近图注判断：出现 overview、architecture、framework、pipeline、flowchart、schematic、结构、架构、框架、流程、方法示意等词才进入方法图优先组；结果、消融、基线或旧方法结构等词会取消这一优先。排序依次比较是否方法图、论文评分（高到低）、论文路径和原图地址，因此同分顺序固定。没有方法图时选择有原图的高分论文；完全没有合格图时保留日期封面和全量日报入口，不沿用昨日选读。

## 图片来源与回退

候选必须匹配当期日期、论文身份、arXiv 版本和正文里实际出现的图片。已有本地 PNG 会核对完整分块、CRC、尺寸、颜色类型和字节 SHA；本地 SVG 核对根元素、viewBox 和标签闭合。正文直接引用的本地图，文件名还要以该图片文件 SHA-256 的前 16 位开头；渲染器映射命中的本地图允许保留历史文件名，但当前完整字节、尺寸和清单 SHA 仍须一致。已有官方图片映射优先复用同论文的本地 PNG 或 SVG，并保留原官方 URL；映射存在但本地文件不合格时，该候选直接丢弃，不会退回官方外链，以免页面实际渲染地址与选图记录不一致。

没有本地映射时，官方外链只允许同一版本的 `https://arxiv.org/html/...` 图片，直接复用已审正文 URL。构建不下载图片、不需要代理凭据，也不将远程 URL 描述成本地封存字节；其可用性与正文的同一官方图片相同。

## 清单与展示复核

选择结果原子写入忽略文件 `data/edition-features-auto.json`，每次构建只保留当期结果，写入时先写临时文件再重命名。该文件不提交；Hugo 在展示前重新核对清单合同、日期、页面类型和论文路径，核对日报与论文源文件 SHA、论文列表成员、图片 Markdown 的精确语法和 SHA；自动封面为本地图时还核对文件存在、字节 SHA、宽高，官方图则要求同一 arXiv 版本。任何一项不符都不会显示自动封面，过期清单不能给新日报套上旧图。旧 `data/edition-features.json` 只在没有自动选图时读取，且仍核对同日期、论文身份和正文成员，作为手工选读的兼容回退。

## 构建验收

`npm run build:verify` 还会验收实际首页、日报和论文页：最新日期、选中成员、选中图片、完整解读入口和原图入口必须一致；首页必须恰好有一个「阅读本期完整速递」主入口，地址指向该日期汇总页，并位于选读之前。`scripts/verify-edition-feature.js` 读取 `data/edition-features-auto.json` 后检查这些关系；选择成功却未渲染，或渲染出的图片、日期、成员与清单不符，都会让构建失败并阻断部署。`hugo` 裸命令不重新选择；本地完整预览也应先执行正常构建。
