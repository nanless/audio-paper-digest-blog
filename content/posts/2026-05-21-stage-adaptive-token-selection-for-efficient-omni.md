### 💡 毒舌点评

论文的核心亮点在于通过精心的实证分析（图2）发现了两个主流om-LLM在层间对视觉/音频token依赖的“块状”衰减模式，这一观察非常扎实且具有启发性。基于此，作者提出了一套完整的、分阶段的、训练免费的token选择框架（SEATS），在工程实现上考虑得相当周全，在极低保留率下仍能保持较高的性能，实用价值明确。短板在于，其核心创新更多体现在对现有技术的巧妙整合与系统设计上，而非提出全新的理论或算法。方法本质上依赖一系列针对特定骨干网络（Qwen-Omni系列）手工调优的启发式规则（如区块边界层、指数衰减因子λ），虽然有效，但缺乏普适性理论支撑和自动适应能力，推广到未知架构（尤其是非Transformer或层数差异大的模型）的潜力存疑。此外，论文未充分讨论其设计选择的边界条件和潜在风险。

### 📌 核心摘要

1. 问题：全模态大语言模型（om-LLMs）需要处理大量时间对齐的视觉和音频token，导致推理计算开销巨大。现有的训练免费token选择方法要么只处理单一模态，要么仅在LLM外部使用固定比例进行剪枝，无法捕捉跨模态token重要性在不同LLM层间的动态演变。
2. 方法核心：本文提出了SEATS（StagE-Adaptive Token Selection），一个三阶段、训练免费的token选择方法。第一阶段在LLM前，使用基于窗口的注意力加权多样性选择（winDivPrune）去除时空冗余。第二阶段在LLM内部中层，采用逐层递减的token保留率（TRR）衰减计划，并通过自上而下的两级预算分配策略（先跨时间窗口，再跨模态），根据查询相关性动态分配token预算。第三阶段在LLM深层，直接移除所有剩余非文本token。
3. 新在何处：与仅在LLM前进行固定比例选择的预处理方法（如OmniZip）和使用固定TRR或浅层注意力进行单次剪枝的内部方法（如FastV、HiDrop）相比，SEATS首次结合了基于实证观察的深度感知、跨层自适应的TRR衰减调度以及查询引导的、跨窗口和模态的动态预算分配。其核心贡献在于揭示了om-LLM的层间依赖模式，并据此设计了适配该模式的三阶段选择流程。
4. 实验结果：在Qwen2.5-Omni-7B上，仅保留10%的视觉和音频token，SEATS实现了9.3倍的FLOPs降低和4.8倍的预填充加速，同时保留了原始性能的96.3%。在35%保留率下，其平均性能（49.3）甚至超过了全token基线（48.7）。在Qwen3-Omni-30B上同样取得了优异表现。具体结果见下表（表3节选）：
    | 方法 | RR (Rv-Ra) | 平均得分 (满分的百分比) |
    | :--- | :--- | :--- |
    | Full tokens | 100 (100-100) | 48.7 (100.0%) |
    | SEATS | 35 (30-65) | 49.3 (101.1%) |
    | SEATS | 25 (20-55) | 48.6 (99.8%) |
    | SEATS | 10 (6-35) | 46.9 (96.3%) |
5. 实际意义：为部署和应用om-LLMs提供了一种有效的推理加速方案，显著降低了计算和内存开销，使其在资源受限设备上的实时应用成为可能。
6. 主要局限性：方法依赖于一系列针对特定骨干网络（如Qwen-Omni）调优的启发式超参数（如区块边界层、衰减因子λ），自动适应新模型架构的能力有待验证；且无法直接应用于流式推理场景。

### 🏗️ 方法概述和架构

SEATS是一个为全模态大语言模型（om-LLMs）设计的、训练免费的、分阶段自适应的token选择推理加速框架。其核心流程是：输入包含视觉、音频和文本token的序列 → 经过预LLM阶段的选择 → 输入到LLM，并在LLM的不同层块内执行不同强度的自适应选择 → 最终在深层移除所有非文本token，仅文本token参与生成。该框架旨在系统性解决三个挑战：预处理阶段的时空冗余、LLM内部不同层对非文本token依赖度的动态变化，以及跨模态重要性随查询和时间窗口的动态变化。

1. 整体流程与阶段划分
SEATS将处理过程明确划分为三个阶段，对应LLM的不同深度，体现了其“阶段自适应”的核心思想：
- 阶段I（预LLM）：在token序列进入LLM主体之前，通过轻量级的冗余消除，缩短输入序列长度。
- 阶段II（LLM内部浅/中层）：在LLM的前向计算过程中，在特定层块执行基于查询感知的、强度逐层递增的token选择。
- 阶段III（LLM内部深层）：在跨模态融合基本完成后，彻底移除所有非文本token，使后续层仅处理文本token，最大化节省计算。

2. 主要组件详解

*   组件1：Window-based DivPrune (winDivPrune) —— 预LLM阶段的多样性选择
    *   功能：在进入LLM之前，去除视觉和音频token中由低运动性或高采样率造成的时空冗余。
    *   内部结构与实现：扩展了用于图像的DivPrune算法（CVPR 2025）。核心是贪心地求解一个“最大化最小距离”问题，以选择一个代表性子集。具体改进如下：a) 局部化计算：为了效率，将距离矩阵计算限制在每个时间窗口和每个模态内部，避免全局计算。b) 注意力加权：使用token自身的注意力分数对距离矩阵的行进行加权，使得更显著的token更有可能被选中。数学上，对于窗口t内的视觉token集合V_t，选择子集S_v满足：S_v = argmax_{S⊆V_t, |S|=k} min_{i,j∈S} d(i,j)，其中距离d基于余弦相似度，且选择过程受注意力权重调制。
       输入输出：输入是经过编码和时间窗口分组的原始视觉token序列和音频token序列。输出是每个窗口内筛选后的、数量更少的视觉和音频token子集，其数量由预设的预LLM token保留率r_s决定（r_s = λ  R，λ>1）。

*   组件2：Block-wise TRR Decay Schedule —— 层间自适应的保留率调度器
    *   功能：根据LLM不同层对非文本token的依赖程度，动态分配每层的token保留率（TRR），实现“浅层多保留，中层渐剪枝，深层全移除”。
    *   内部结构与实现：基于图2的实证观察，将L层LLM划分为三个块：
        *   浅层块：依赖度高，不进行剪枝，TRR = r_s（即预LLM阶段的保留率）。
           中层块：依赖度逐渐降低，执行渐进式剪枝。该块又被细分为三个子块，TRR值按照公式 r_m_i = r_m_{i-1} - δ  e^{i-1} 指数衰减。其中δ是一个可由全局保留率R、缩放因子λ和各区块边界层索引解析计算出的缩放因子（推导见附录A），确保总TRR符合预算。这种指数衰减设计使得剪枝在中层块内也呈现“先缓后急”的态势。
        *   深层块：依赖度可忽略，TRR直接设为0，移除所有非文本token。
    *   输入输出：输入是当前层的全局保留率R和架构参数（层数L，区块边界）。输出是分配给当前层的具体TRR值r_l。

*   组件3：Top-down Token Budget Allocation —— 查询引导的跨窗口/跨模态预算分配
    *   功能：在LLM的每个中层块内，根据当前层的TRR，将有限的token预算动态、合理地分配给不同的时间窗口以及窗口内的不同模态。
    *   内部结构与实现：采用两级自上而下的分配策略：
        1.  跨时间窗口分配：计算每个窗口t与查询的相关性得分S_t。S_t是窗口内视觉相关性得分S_{t,v}和音频相关性得分S_{t,a}的平均值。S_{t,v}和S_{t,a}通过查询token（最后一个文本token）与该窗口内所有视觉/音频token的注意力分数均值，并经温度缩放（τ=0.1）的softmax归一化得到。窗口t分配到的总预算B_t ∝ S_t。
        2.  窗口内跨模态分配：在窗口t内，根据视觉模态和音频模态各自的层预算（r_vN_v, r_aN_a）以及它们与查询的相关性（S_{t,v}, S_{t,a}），将总预算B_t进一步分配为视觉预算B_{t,v}和音频预算B_{t,a}。具体公式如论文式(1)所示，本质上是按模态的“相关性加权预算”进行比例分配。
    *   输入输出：输入是当前层的视觉和音频TRR（r_v, r_a），所有token的序列，以及查询token。输出是每个窗口、每种模态分配到的具体token预算数量（B_{t,v}, B_{t,a}）。

*   组件4：Query-guided Token Selection —— 执行选择
    *   功能：根据预算分配结果，在每个窗口内实际执行视觉和音频token的筛选。
    *   内部结构与实现：对于窗口t的视觉token，按查询到这些token的注意力分数降序排序，保留前B_{t,v}个。音频token选择方式同理。这是一种简单、高效的基于相关性的选择策略。
    *   输入输出：输入是窗口t内的原始视觉/音频token及其注意力分数，以及预算B_{t,v}/B_{t,a}。输出是筛选后保留的token集合。

3. 组件间数据流与交互
数据流是线性的，但决策是条件性的。输入token序列首先通过winDivPrune进行初步筛选，送入LLM。在LLM的前向传播中，当进入中层块时，Block-wise TRR Decay Schedule根据当前层索引决定该层的保留率。接着，Top-down Token Budget Allocation利用当前层的保留率和查询信息，计算出每个窗口和模态的精确预算。最后，Query-guided Token Selection根据预算执行实际筛选，未被选中的token被丢弃，剩余token继续向后传播。在深层块，Block-wise TRR Decay Schedule触发，所有非文本token被直接移除。

4. 关键设计选择及动机
*   三阶段架构的动机：源于对不同阶段冗余性质不同的深刻理解。预处理阶段处理时空冗余，内部浅层因注意力尚未校准而避免剪枝，内部中层处理与查询相关的动态冗余，深层则利用融合完成后的冗余。这是对“一刀切”式单点剪枝的根本改进。
*   基于实证观察划分区块：方法的关键超参数（区块边界）并非凭空设定，而是直接来源于图2对两个主流om-LLM的实验分析，使设计更具解释性和针对性。
*   自上而下分配策略的动机：先决定“总盘子”如何分给时间（窗口），再决定“小盘子”如何分给模态，符合信息处理的层级性，比全局统一比例或完全独立分配更能捕捉查询驱动的、跨模态的动态重要性。
*   训练免费：所有选择标准（注意力分数、多样性距离）均来自模型前向传播的中间状态，无需额外训练或微调，保证了即插即用的通用性。

![SEATS方法示意图](https://arxiv.org/html/2605.20035v1/x5.png)
图3展示了SEATS的整体架构。流程从左到右：输入序列首先经过预LLM阶段的winDivPrune进行初步筛选。随后进入LLM，其中浅层（Shallow Block）保持所有token。在中层（Middle Block），每层应用Block-wise TRR Decay Schedule确定保留率，并通过Top-down Token Budget Allocation（先跨窗口，再窗口内跨模态）动态分配预算，由Query-guided Token Selection执行选择。在深层（Late Block），所有非文本token被移除。

### 💡 核心创新点

1.  基于实证的阶段划分与自适应剪枝策略：通过实验揭示om-LLM层间对视觉/音频token依赖的“块状”衰减模式，并据此设计了三阶段（预处理、内部渐进式、内部全移除）的处理流程和与之匹配的token保留率（TRR）指数衰减调度器。这突破了现有方法仅在单一阶段（前或内）进行固定比例剪枝的局限，使剪枝强度与模型内部的信息流动动态对齐。
2.  自上而下的跨窗口、跨模态动态预算分配：提出了查询引导的两级预算分配机制。第一级根据每个时间窗口与查询的相关性，在窗口间动态分配token预算；第二级在每个窗口内，根据视觉和音频子模态与查询的相关性，在模态间再次动态分配预算。这种机制比固定比例分配更能适应多模态数据中关键信息可能出现在任意时间点和任意模态的特点。
3.  预处理阶段的窗口化多样性选择：将针对静态图像的多样性选择方法（DivPrune）扩展到全模态的时空上下文中，提出了winDivPrune。通过限制在时间窗口内计算并引入注意力加权，在去除时空冗余的同时，保留了更具代表性的token子集，为后续的LLM内部选择奠定了良好基础。

### 📊 实验结果

论文在五个音视频理解基准（WorldSense, Daily-Omni, OmniVideoBench, Video-MME, LVOmniBench）上，对两个主流om-LLM（Qwen2.5-Omni-7B, Qwen3-Omni-30B）进行了全面评估。

| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Full tokens | 100 (100-100) | 46.7 | 64.0 | 34.1 | 65.3 | 33.3 | 48.7 (100.0%) |
| SEATS | 35 (30-65) | 46.2 | 62.1 | 35.0 | 66.8 | 36.2 | 49.3 (101.1%) |

### 🚨 局限与问题

1. 论文明确承认的局限：
- 方法依赖于一组启发式超参数（如区块边界层、衰减因子λ），这些参数是针对特定骨干网络（Qwen-Omni）调优的，自动适应新om-LLM架构的能力有待研究。
- 当前框架无法直接应用于流式推理场景，因为其设计（如计算窗口相关性、进行多阶段选择）依赖于完整的输入序列。

2. 审稿人发现的潜在问题：
- 超参数泛化性：区块边界Ls, Lm1, Lm2, Ll是方法性能的关键，但其确定过程依赖于对目标模型的预实验（如图2），这增加了方法迁移到新架构的成本。论文未讨论这些边界在模型架构变化（如层数、注意力模式变化）时应如何调整，也缺乏自动化的边界发现机制。
- 相关性度量的局限性：使用最后一个文本token的注意力分数作为查询相关性的代理，可能在多轮对话或复杂推理任务中不够准确。方法未探讨其他潜在的查询相关性度量（如中间层文本token的注意力聚合）。
- 动态预算分配的开销：在每一层的中层块内，都需要重新计算所有窗口和模态的查询相关性并进行预算分配。虽然论文提到代码已优化，但这部分计算开销在极端追求低延迟的场景下可能成为瓶颈。论文未单独分析这部分开销占总预填充时间的比例。
- 缺乏对失败案例的分析：论文展示了优异的平均性能，但未分析在哪些特定样本或任务类型上SEATS可能失效（例如，高度依赖音频细微差别的任务、关键视觉信息出现在极短瞬间的任务）。理解失败模式有助于进一步改进方法。
- 潜在的信息丢失风险：在深层阶段（Stage III）直接移除所有非文本token，假设“非文本token不再需要”。虽然实验（图2）支持这一假设，但对于某些需要长程音频-视频对齐推理的任务，这种激进移除可能丢失潜在有用信息，导致性能下降。论文未深入讨论这一设计的适用边界。
