### 💡 毒舌点评

本文最大的贡献是“立规矩”——为评估多模态大模型最核心也最容易被取巧的“音视频联合推理”能力，设立了一个高门槛、系统化的考卷（JointAVBench），其严格的音视频依赖性控制（100%相关）和多层次任务分类学设计堪称标杆。短板在于，这份“考卷”的命题素材（短片数据集SF20K）来源相对单一，可能无法完全代表现实世界中音视频交织的无限复杂性，且流水线高度依赖当前最强的LLM，其生成质量上限受限于“教师模型”的能力。

### 📌 核心摘要

1.  解决的问题：现有用于评估多模态大语言模型（Omni-LLMs）音视频联合理解能力的基准测试存在不足，或缺乏严格的音视频依赖性控制，或覆盖的音频类型单一，或忽略了多场景推理的复杂性，导致无法对模型进行严格全面的评估。
2.  方法核心：提出JointAVBench，这是一个全新的基准。其核心在于一个精心设计的三维分类体系：5种认知维度（如时序、情节）、4种音频信息类型（语音、声学事件、音乐、人声特征）和3种场景跨度（单场景、跨场景、全场景）。基于此构建了15个需要严格音视频联合推理的任务。同时，提出一个三阶段半自动流水线来生成高质量问题-答案对：全模态描述生成、问答对创建、严格的质量控制（通用检查+任务特定检查+干扰项生成），并辅以人工验证。
3.  创新点：这是首个专注于严格音视频关联和多场景推理的综合评估基准。其分类体系系统且全面，半自动构建流水线在保证数据质量（100%音视频相关率）的同时降低了成本。
4.  主要实验结果：评估了主流模型，最好的Omni-LLM（Gemini2.5-Pro）平均准确率仅为62.6%，虽显著优于单模态基线，但仍表明巨大提升空间。Omni-LLMs在大多数任务上优于Video-LLMs和Audio-LLMs，但在情感识别和空间推理等任务上反而落后。跨场景任务性能显著低于单场景任务，且场景数量增加会导致性能急剧下降。
5.  实际意义：为评估和推动具有真正音视频联合推理能力的Omni-LLMs提供了一个关键工具和方向标。揭示了当前模型在跨场景、情感和空间音视频融合方面的关键短板。
6.  主要局限性：数据集完全源自SF20K一个数据集，可能存在分布偏差。任务分类虽全面，但可能未涵盖所有音视频联合推理的维度。实验受计算资源限制，未能评估所有可能的模型。

### 🏗️ 模型架构

本文并未提出一个新的模型架构，而是提出了一个用于评估现有模型的基准测试构建方法和数据集。其核心是数据生成流水线的架构。

下图展示了JointAVBench的三阶段半自动构建流水线。

![JointAVBench构建流水线示意图](/audio-paper-digest-blog/images/iclr-2026/2026-05-04/Zg1YH8R5GG-5.png)
*图1 JointAVBench三阶段半自动构建流水线：(a) 全模态描述生成（场景识别、视频/语音/人声特征/声学事件/音乐描述）、(b) 任务模板驱动的问答对生成（单/多/全场景）、(c) 干扰项生成与多级质量控制*

流水线架构详解：
1.  阶段一：全模态描述生成
    *   输入：长视频（来自SF20K数据集）。
    *   组件与数据流：
        *   场景识别：使用PySceneDetect将长视频分割成语义一致的场景片段。
        *   视频描述生成：对每个片段，使用Qwen2.5-VL生成详细的视觉描述。
        *   音频描述生成：使用Qwen2.5-Omni分别为人声特征、声学事件与音乐生成独立描述。由于现有模型难以区分声学事件和音乐，它们先被一起生成，然后通过一个LLM进行后处理分离。语音转录使用Whisper-v3以获得准确的时间戳和文本。
        *   描述精炼：使用Qwen-2.5对生成的音频描述进行清理，减少幻觉，并确保人声特征与转录对齐。
    *   输出：每个视频场景的多模态描述集（视觉、语音、人声特征、声学事件、音乐）。

2.  阶段二：问答对创建
    *   输入：全模态描述。
    *   组件与数据流：
        *   任务定义与模板：基于预定义的15种任务（如表2所示），为每个任务设计问题模板。例如，“说话人空间定位”任务仅需单个场景的视觉描述和人声特征描述。
        *   问答生成：使用Qwen2.5根据模板和指定的模态描述输入生成问题-答案对。关键设计是严格限制输入描述的模态和场景范围，以确保生成的问题必须依赖音视频联合推理。
        *   区间验证：对于跨场景任务，使用特定的提示（图16）来验证生成的问题确实需要跨越多个场景的信息。
    *   输出：初始的、包含解释的问答对集合。

3.  阶段三：质量控制
    *   输入：初始问答对。
    *   组件与数据流：
        *   通用检查：使用LLM进行模态检查（是否真正需要音视频）、逻辑检查（答案是否可从上下文推导）、格式检查和内容检查。
        *   任务特定检查：根据任务类型执行不同的检查，例如序列检查（确保排序任务元素顺序正确）、歧义检查（过滤掉过于宽泛的问题）、音频信号类型检查（确保声学事件/音乐信息无法从视觉推断）。
        *   干扰项生成：为通过验证的正确答案生成三个合理的错误选项，形成多选题。
        *   人工验证：由专业标注员根据正确性、信息准确性、音视频依赖性和问题难度进行最终筛选和修正，最终保留2,853个高质量问题。
    *   输出：最终的高质量、多选题形式的基准数据集。

关键设计选择：整个架构的核心在于“受控生成”。通过精心设计任务模板并严格限制生成模型的输入上下文（仅提供必要的模态和场景描述），从源头上确保了问题对音视频联合推理的强制依赖性，这是对之前基准的关键改进。

### 💡 核心创新点

1.  首个专注严格音视频关联的综合评估基准：通过设计100%需要音视频联合推理的任务，并量化验证（人类评估相关率94.5%），解决了现有基准音视频依赖性弱或无依赖的核心缺陷。
2.  系统化的多维任务分类学：首次将评估维度系统化为认知维度（时序、空间、情感、情节、长程）、音频类型（语音、人声特征、声学事件、音乐）和场景复杂度（单、多、全场景），形成了15个具体任务（如表2所示），实现了细粒度的能力探测。
3.  高效的半自动数据生成与质量控制流水线：提出了一套完整的、基于当前最先进LLM/VLM/ALM的流水线，结合了模板引导生成、严格的输入控制和多级验证（通用检查、任务特定检查、人工复核），在保证数据集质量和规模（2,853个问题）的同时，显著降低了人工标注成本。

### 📊 实验结果

主要基准与指标：在自建的JointAVBench数据集上，采用准确率（Accuracy） 作为指标，评估了15个任务的性能。

主要对比结果（表3）：
| 模型类型 | 模型名称 | 参数规模 | 平均准确率 | 关键亮点/短板任务 |
| :--- | :--- | :--- | :--- | :--- |
| Omni-LLMs | Gemini2.5-Pro | - | 62.6% | 最佳平均性能；在STL、VSSR等语音相关任务强，但在SPL、SPER等任务弱 |
| | Qwen3-Omni | 30B | 62.1% | 与第一名接近；在MPTI（音乐基调）、CRI（角色关系）上表现优异 |
| | Qwen2.5-Omni | 7B | 56.2% | 相较于其Video-LLM版本（InternVL-2.5）提升显著，证明了原生多模态融合的优势 |
| | Gemini2.5-Flash | - | 52.6% | |
| Video-LLMs | InternVL-2.5 | 8B | 51.3% | Video-LLM中的最佳，但在多数任务上仍落后于同规模Omni-LLM |
| | GPT-4o | - | 43.3% | 表现意外较差，可能因为未输入时间戳信息限制了其时序推理能力 |
| Audio-LLMs | Kimi-Audio | 7B | 45.9% | Audio-LLM中的最佳，但在需要强视觉理解的任务上表现不足 |

关键发现与消融分析：
1.  跨音频类型性能不均（图4）：模型在声学事件和音乐相关任务上表现较好，但在人声特征（如情感、空间）和语音相关任务上表现显著较差。

    图4结论：模型对抽象音频信息（人声特征、语音）的理解和融合能力是当前主要瓶颈。
2.  跨场景复杂度性能退化（图5）：单场景任务性能最好，多场景任务性能急剧下降，全场景任务性能有所回升（因聚焦全局叙事而非细节）。

    图5结论：跨场景推理（Multi-scene）是当前模型的最大挑战。
3.  跨认知维度性能不均（图6）：Omni-LLMs在时序和长程推理上优势明显，但在情感和空间任务上甚至不如单模态模型。

    图6结论：简单的多模态拼接可能引入干扰，模型尚未学会在所有维度上有效融合音视频信息以提升情感和空间推理。
4.  场景数量对性能的影响（图7）：随着视频中场景数量的增加，模型在跨场景任务上的性能线性下降。

    图7结论：当前模型处理长序列、多上下文音视频信息的能力非常有限。
5.  模态融合有效性（表4）：分析了Omni-LLMs相对于其单模态基线的提升。Qwen2.5-Omni在音视频（A+V）联合模式下的性能，在绝大多数任务上都优于仅用视频（V）或仅用音频（A），证实了有效的融合能带来收益。
