## 毒舌点评
这篇论文的亮点在于它敢于拥抱一个相对小众但理论优美的范式（离散流匹配）去挑战多模态统一这个“圣杯”任务，并且用扎实的实验和开源证明了这不仅是可行的，而且在检索和交互等“融合”场景下比粗暴拼接的AR模型更优雅。不过，当它自豪地宣布在理解任务上与AR模型“打平”或“略优”时，也恰恰暴露了当前流匹配模型在处理高度结构化的语言生成任务时，效率和纯度上可能存在的隐性短板——毕竟，用迭代去噪来逐字生成文本，怎么看都像用液压机去雕花。

## 核心摘要
1.  要解决什么问题：现有的多模态基础模型大多基于自回归（AR）架构，难以平衡理解与生成任务。混合或解耦架构虽然有所改进，但结构冗余，不支持跨模态检索等需要深度特征融合的任务。
2.  方法核心是什么：提出NExT-OMNI，一个首个完全基于离散流匹配（DFM）范式的开源全模态基础模型。通过统一的模型架构，使用离散流匹配进行训练，原生支持文本、图像、视频、音频之间的任意到任意的理解与生成。
3.  与已有方法相比新在哪里：
    *   范式创新：摒弃AR和混合架构，采用DFM作为核心建模方法，实现并行去噪和双向信息融合。
    *   架构创新：设计了基于统一表示的模态编码器（支持理解与生成）和轻量级模态解码头，通过深度多模态自注意力进行特征融合，而非使用多个编码器或MoE模块。
    *   训练策略创新：引入了动态长度生成策略（DGS）和基于重建损失的自适应缓存加速，提升了理解能力和推理效率。
4.  主要实验结果如何：在多个基准测试上表现出色。关键结果对比如下表所示：

| 任务类别 | 基准测试 | 指标 | 最强基线 (OpenOmni / FUDOKI) | NExT-OMNI | 提升 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 多模态理解 | OmniBench + WorldSense + AV-Odyssey | 平均分 | 36.5 | 39.7 | +3.2 |
| 语音交互 | Spoken QA (Llama Q.) | S→S | 48.1 (OpenOmni) | 47.4 | -0.7 |
| 视觉交互 | OpenING | GPT评分平均 | 50.4 (Anole) | 55.0 | +4.6 |
| 多模态检索 | InfoSeek + OVEN + ... | Top5平均准确率 | 31.8 (MMaDA) | 32.9 | +1.1 |

5.  实际意义是什么：为多模态统一建模提供了一种新的、更简洁高效的范式（DFM）。模型开源，推动了该领域的研究。
6.  主要局限性是什么：论文承认受限于资源，仅在7B参数规模上进行验证，其潜力未完全释放。此外，在纯语音生成（S→S）任务上未取得最佳成绩。

## 详细分析

NExT-OMNI 的整体架构是一个端到端的Transformer骨干网络，旨在通过统一的离散流匹配范式处理任意模态间的理解、生成与检索任务。

![NExT-OMNI 总体框架概览](/audio-paper-digest-blog/images/iclr-2026/2026-05-03/odatOcBi61-0.png)
图1：NExT-OMNI框架总览。该模型支持任何模态到任何模态的操作。它通过一个统一的表示进行跨模态检索，并使用并行的流匹配采样过程加速任何到任何的生成。指令可以被编码，而响应可以被解码。

核心组件与流程：
1.  模态编码器（Modality Encoders）：
    *   视觉编码器：基于CLIP-ViT-Large初始化，通过统一表示训练（包含VQVAE重建损失和对比语义损失）后，能同时支持图像理解和生成。采用多码本量化（MCQ），最终码本大小为`4×4096`。
    *   音频编码器：基于Whisper-Turbo初始化，同样经过统一表示训练（包含VQVAE重建损失和字幕级语义损失），支持音频理解和生成。采用`2×2048`的多码本。
    *   文本分词器：使用标准的文本tokenizer将文本转换为离散token。
    *   作用：将不同模态的输入（图像、音频、文本）统一转换为离散的token序列。其关键设计在于，同一个编码器既服务于理解任务（提供特征），也服务于生成任务（提供要预测的离散目标），这是“统一表示”的核心。

![NExT-OMNI 方法流程图](/audio-paper-digest-blog/images/iclr-2026/2026-05-03/odatOcBi61-1.png)
图2：NExT-OMNI框架流程。该图展示了模态编码器（视觉、音频）、骨干网络（自注意力+FFN）以及用于生成的模态解码头（视觉、音频）。训练时使用离散流匹配的目标（速度预测），损失函数包括重建损失和交叉熵损失。图中还展示了跨模态检索基于统一表示进行。

2.  骨干网络（Backbone）：
    *   基于预训练的自回归LLM（Qwen2.5-7B）初始化。
    *   经过预训练（PT）、继续预训练（CPT）和监督微调（SFT）三阶段训练。
    *   关键设计：在所有层都使用多模态自注意力，让不同模态的token能够深度交互和融合信息，而非依赖额外的解耦模块（如MoE）。这使得学习到的表示具有更好的跨模态统一性。

3.  模态解码头（Modality Heads）：
    *   设计了独立的轻量级头（Vision Head, Audio Head），用于从骨干网络的输出特征中预测对应模态的离散token索引（对于多码本，则是预测多个子码本的索引）。
    *   采用自回归的多子码本预测方式（如图7左所示），以保证预测稳定性。
    *   作用：在生成任务中，根据噪声输入`xt`预测干净的目标token `x1`。在理解任务中，模型通过迭代去噪最终能确定地输出文本响应。

4.  统一表示与跨模态检索：
    *   模型训练时，在所有层都进行深度跨模态特征融合，产生了一个富含多模态信息的统一表示（通常取序列最后一个token的特征，如`<EOS>`）。
    *   这个统一表示可以直接用于跨模态检索任务，无需像解耦架构那样分别提取不同模态的特征再计算相似度。

整体数据流：输入多模态序列 -> 各模态编码器转化为离散token序列 -> 与文本token混合成统一序列 -> 输入骨干网络进行深度融合（在训练时加入对应时间步的噪声`xt`）-> 解码头预测目标token（训练时预测干净token `x1`，生成时预测并去噪）。

1.  首次将离散流匹配（DFM）范式系统性地应用于全模态统一模型。
    *   局限：之前多模态模型多依赖AR或连续扩散/流匹配，离散流匹配在语言建模中虽有探索，但未在包含图像、音频的全模态场景中得到验证。
    *   如何起作用：DFM从完全噪声的离散序列出发，通过迭代并行去噪来生成目标序列。它结合了扩散模型的并行性和离散空间的特性，理论上更适配统一的离散token表示。
    *   收益：为统一多模态建模提供了新的、可能更高效的范式。实验表明，基于DFM的架构在生成、尤其是需要深度特征融合的检索任务上具有优势。

2.  设计了支持理解与生成的统一模态编码器。
    *   局限：许多现有模型为理解和生成使用不同的编码器（解耦设计），导致结构冗余。
    *   如何起作用：通过联合优化重建损失（保留细节）和语义对齐损失（对齐高级语义），使单一编码器生成的统一表示能同时服务于两种任务。
    *   收益：简化了模型结构，并为基于统一表示的检索等任务打下基础。消融实验（表5）表明，统一表示在检索任务上显著优于解耦表示。

3.  提出并验证了重建损失反馈增强的统一表示训练。
    *   局限：单纯的语义对齐可能导致表示丢失生成任务所需的细节信息。
    *   如何起作用：在DFM主损失之外，复用编码器预训练时的重建损失（`LV_rec`, `LA_rec`），约束骨干网络输出的特征保留细节。
    *   收益：增强了表示的细粒度信息，从而提升了生成和检索任务的性能（表5）。

4.  设计了动态长度生成策略（DGS）和自适应缓存加速。
    *   局限：DFM的固定长度生成可能不适应变化的理解任务输出长度。
    *   如何起作用：DGS在训练时填充响应，在推理时根据`<EOS>`置信度动态扩展输出块，实现灵活长度生成。自适应缓存则利用了DFM多步去噪时特征变化小的特性，缓存指令部分特征并自适应更新响应部分特征。
    *   收益：DGS显著提升了理解任务性能（表5）。缓存与并行解码结合，实现了比AR架构更快的推理速度（1.2倍加速）。

- 训练数据：
    - 规模：详细信息见表8。PT阶段：图像-文本对~57M，音频相关~22M，纯文本~4M。CPT阶段：图像相关~22M，视频~12M，音频相关~13.3M，文本~2.3M。SFT阶段：各类指令数据总计~18.3M。
    - 来源：大量使用公开数据集（LAION， DataComp， LibriSpeech， WenetSpeech， AudioCaps， MMC4， OmniCorpus， OpenVid等）及专有数据。
    - 预处理：图像分辨率从256×256��升到384×384；音频最大15秒，长音频分块处理；视频均匀抽8帧作为多图像输入。
    - 数据增强：使用FLUX模型合成图像生成数据（Gen-5M），使用MMEvol算法合成高复杂度的理解数据（Und-4M）。
- 损失函数：
    - 主要损失（DFM）：`Lce`（公式2），即在时间`t`上采样的期望交叉熵损失。
    - 辅助损失：`overall`损失（公式3）`Loverall = λ1·Lce + λ2·LV_rec + λ3·LA_rec`。其中`LV_rec`和`LA_rec`是模态编码器预训练时的重建损失。
    - 损失平衡：采用GradNorm方法动态调整`λ1`, `λ2`, `λ3`，确保各损失项梯度贡献均衡。
- 训练策略：
    - 三阶段训练：
        1.  预训练（PT）：小分辨率（256×256），短上下文（2K），对齐模态。
        2.  继续预训练（CPT）：提升分辨率（384×384），长上下文（16K），引入视频和长音频，支持多轮交互。
        3.  监督微调（SFT）：使用各类指令数据，装备任何到任何的生成能力。
    - 效率优化：同一批次内只训练一种模态，通过多任务交错训练和梯度累积实现联合训练，提升1.4倍效率。
    - 学习率：模态编码器&解码器预训练阶段为`2e-5`，CPT和SFT阶段为`1e-6`；骨干网络部分在SFT阶段为`1e-4`。
- 关键超参数：
    - 模型大小：骨干网络基于Qwen2.5-7B，模态编码器基于CLIP-ViT-Large和Whisper-Turbo，模态头参数约128M。
    - 量化码本：视觉`4×4096`，音频`2×2048`。
    - 生成设置：CFG概率`0.1`，理解任务响应填充块大小`64`。
    - 流匹配调度：采用`βt = c (t/(1-t))^a`，其中`c=3`, `a=0.9`（附录A）。
- 训练硬件：论文中未说明具体的GPU/TPU型号、数量和训练时长。
- 推理细节：
    - 解码策略：采用Euler求解器模拟连续时间马尔可夫链过程（附录A），实现并行去噪。
    - 加速技巧：结合上述的自适应缓存和动态长度生成策略。
- 正则化：未明确说明使用Dropout等正则化手段。

消融结论：
1.  将AR替换为DFM，生成和检索任务提升，但理解任务下降。
2.  从解耦表示转为统一表示，检索任务大幅提升，但因粒度冲突导致理解与生成任务轻微下降。
3.  引入动态长度生成策略（DGS），理解任务性能显著恢复，接近AR基线。
4.  加入重建损失，所有任务（尤其是生成和检索）得到全面提升，验证了细粒度信息保留的重要性。

### 🏗️ 模型架构

NExT-OMNI 的整体架构是一个端到端的Transformer骨干网络，旨在通过统一的离散流匹配范式处理任意模态间的理解、生成与检索任务。

![NExT-OMNI 总体框架概览](/audio-paper-digest-blog/images/iclr-2026/2026-05-03/odatOcBi61-0.png)
图1：NExT-OMNI框架总览。该模型支持任何模态到任何模态的操作。它通过一个统一的表示进行跨模态检索，并使用并行的流匹配采样过程加速任何到任何的生成。指令可以被编码，而响应可以被解码。

核心组件与流程：
1.  模态编码器（Modality Encoders）：
    *   视觉编码器：基于CLIP-ViT-Large初始化，通过统一表示训练（包含VQVAE重建损失和对比语义损失）后，能同时支持图像理解和生成。采用多码本量化（MCQ），最终码本大小为`4×4096`。
    *   音频编码器：基于Whisper-Turbo初始化，同样经过统一表示训练（包含VQVAE重建损失和字幕级语义损失），支持音频理解和生成。采用`2×2048`的多码本。
    *   文本分词器：使用标准的文本tokenizer将文本转换为离散token。
    *   作用：将不同模态的输入（图像、音频、文本）统一转换为离散的token序列。其关键设计在于，同一个编码器既服务于理解任务（提供特征），也服务于生成任务（提供要预测的离散目标），这是“统一表示”的核心。

![NExT-OMNI 方法流程图](/audio-paper-digest-blog/images/iclr-2026/2026-05-03/odatOcBi61-1.png)
图2：NExT-OMNI框架流程。该图展示了模态编码器（视觉、音频）、骨干网络（自注意力+FFN）以及用于生成的模态解码头（视觉、音频）。训练时使用离散流匹配的目标（速度预测），损失函数包括重建损失和交叉熵损失。图中还展示了跨模态检索基于统一表示进行。

2.  骨干网络（Backbone）：
    *   基于预训练的自回归LLM（Qwen2.5-7B）初始化。
    *   经过预训练（PT）、继续预训练（CPT）和监督微调（SFT）三阶段训练。
    *   关键设计：在所有层都使用多模态自注意力，让不同模态的token能够深度交互和融合信息，而非依赖额外的解耦模块（如MoE）。这使得学习到的表示具有更好的跨模态统一性。

3.  模态解码头（Modality Heads）：
    *   设计了独立的轻量级头（Vision Head, Audio Head），用于从骨干网络的输出特征中预测对应模态的离散token索引（对于多码本，则是预测多个子码本的索引）。
    *   采用自回归的多子码本预测方式（如图7左所示），以保证预测稳定性。
    *   作用：在生成任务中，根据噪声输入`xt`预测干净的目标token `x1`。在理解任务中，模型通过迭代去噪最终能确定地输出文本响应。

4.  统一表示与跨模态检索：
    *   模型训练时，在所有层都进行深度跨模态特征融合，产生了一个富含多模态信息的统一表示（通常取序列最后一个token的特征，如`<EOS>`）。
    *   这个统一表示可以直接用于跨模态检索任务，无需像解耦架构那样分别提取不同模态的特征再计算相似度。

整体数据流：输入多模态序列 -> 各模态编码器转化为离散token序列 -> 与文本token混合成统一序列 -> 输入骨干网络进行深度融合（在训练时加入对应时间步的噪声`xt`）-> 解码头预测目标token（训练时预测干净token `x1`，生成时预测并去噪）。

### 💡 核心创新点

1.  首次将离散流匹配（DFM）范式系统性地应用于全模态统一模型。
    *   局限：之前多模态模型多依赖AR或连续扩散/流匹配，离散流匹配在语言建模中虽有探索，但未在包含图像、音频的全模态场景中得到验证。
    *   如何起作用：DFM从完全噪声的离散序列出发，通过迭代并行去噪来生成目标序列。它结合了扩散模型的并行性和离散空间的特性，理论上更适配统一的离散token表示。
    *   收益：为统一多模态建模提供了新的、可能更高效的范式。实验表明，基于DFM的架构在生成、尤其是需要深度特征融合的检索任务上具有优势。

2.  设计了支持理解与生成的统一模态编码器。
    *   局限：许多现有模型为理解和生成使用不同的编码器（解耦设计），导致结构冗余。
    *   如何起作用：通过联合优化重建损失（保留细节）和语义对齐损失（对齐高级语义），使单一编码器生成的统一表示能同时服务于两种任务。
    *   收益：简化了模型结构，并为基于统一表示的检索等任务打下基础。消融实验（表5）表明，统一表示在检索任务上显著优于解耦表示。

3.  提出并验证了重建损失反馈增强的统一表示训练。
    *   局限：单纯的语义对齐可能导致表示丢失生成任务所需的细节信息。
    *   如何起作用：在DFM主损失之外，复用编码器预训练时的重建损失（`LV_rec`, `LA_rec`），约束骨干网络输出的特征保留细节。
    *   收益：增强了表示的细粒度信息，从而提升了生成和检索任务的性能（表5）。

4.  设计了动态长度生成策略（DGS）和自适应缓存加速。
    *   局限：DFM的固定长度生成可能不适应变化的理解任务输出长度。
    *   如何起作用：DGS在训练时填充响应，在推理时根据`<EOS>`置信度动态扩展输出块，实现灵活长度生成。自适应缓存则利用了DFM多步去噪时特征变化小的特性，缓存指令部分特征并自适应更新响应部分特征。
    *   收益：DGS显著提升了理解任务性能（表5）。缓存与并行解码结合，实现了比AR架构更快的推理速度（1.2倍加速）。

### 🔬 细节详述

- 训练数据：
    - 规模：详细信息见表8。PT阶段：图像-文本对~57M，音频相关~22M，纯文本~4M。CPT阶段：图像相关~22M，视频~12M，音频相关~13.3M，文本~2.3M。SFT阶段：各类指令数据总计~18.3M。
    - 来源：大量使用公开数据集（LAION， DataComp， LibriSpeech， WenetSpeech， AudioCaps， MMC4， OmniCorpus， OpenVid等）及专有数据。
    - 预处理：图像分辨率从256×256��升到384×384；音频最大15秒，长音频分块处理；视频均匀抽8帧作为多图像输入。
    - 数据增强：使用FLUX模型合成图像生成数据（Gen-5M），使用MMEvol算法合成高复杂度的理解数据（Und-4M）。
- 损失函数：
    - 主要损失（DFM）：`Lce`（公式2），即在时间`t`上采样的期望交叉熵损失。
    - 辅助损失：`overall`损失（公式3）`Loverall = λ1·Lce + λ2·LV_rec + λ3·LA_rec`。其中`LV_rec`和`LA_rec`是模态编码器预训练时的重建损失。
    - 损失平衡：采用GradNorm方法动态调整`λ1`, `λ2`, `λ3`，确保各损失项梯度贡献均衡。
- 训练策略：
    - 三阶段训练：
        1.  预训练（PT）：小分辨率（256×256），短上下文（2K），对齐模态。
        2.  继续预训练（CPT）：提升分辨率（384×384），长上下文（16K），引入视频和长音频，支持多轮交互。
        3.  监督微调（SFT）：使用各类指令数据，装备任何到任何的生成能力。
    - 效率优化：同一批次内只训练一种模态，通过多任务交错训练和梯度累积实现联合训练，提升1.4倍效率。
    - 学习率：模态编码器&解码器预训练阶段为`2e-5`，CPT和SFT阶段为`1e-6`；骨干网络部分在SFT阶段为`1e-4`。
- 关键超参数：
    - 模型大小：骨干网络基于Qwen2.5-7B，模态编码器基于CLIP-ViT-Large和Whisper-Turbo，模态头参数约128M。
    - 量化码本：视觉`4×4096`，音频`2×2048`。
    - 生成设置：CFG概率`0.1`，理解任务响应填充块大小`64`。
    - 流匹配调度：采用`βt = c (t/(1-t))^a`，其中`c=3`, `a=0.9`（附录A）。
- 训练硬件：论文中未说明具体的GPU/TPU型号、数量和训练时长。
- 推理细节：
    - 解码策略：采用Euler求解器模拟连续时间马尔可夫链过程（附录A），实现并行去噪。
    - 加速技巧：结合上述的自适应缓存和动态长度生成策略。
- 正则化：未明确说明使用Dropout等正则化手段。
