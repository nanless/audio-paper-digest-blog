### 📌 核心摘要

这篇论文旨在解决歌唱语音转录（SVT）任务中存在的多阶段流水线复杂、音词对齐困难以及对分布外数据泛化能力差的问题。方法核心是构建一个基于大型音频语言模型（LALM）的统一自回归生成模型 VocalParse，并通过设计交错的音词提示格式（将每个歌词词与其对应的音符序列交错拼接）和链式思维（CoT）提示策略（先生成纯歌词作为语义上下文，再生成交错序列），在单一解码框架内联合建模歌词、旋律及其对应关系。与已有方法相比，新在两个方面：一是提出了直接生成结构化音词交错序列的端到端范式，无需复杂的后处理或多模块级联；二是通过 CoT 提示巧妙平衡了结构化生成与预训练 LALM 的语义建模能力。主要实验结果表明，VocalParse 在多个基准数据集上达到了先进水平。例如，在 Opencpop 数据集的自动旋律转录任务中，其音频-歌词条件下的 MAE_pitch、MAE_note、MAE_dur 和 Num_note 分别达到 0.35， 0.43， 0.33 和 0.11，优于 ROSVOT 等基线；其歌词转录的 WER 在三个数据集上分别为 3.79%， 5.69%， 8.16%，与专用 ASR 模型相当。此外，由其标注的数据能有效提升下游歌唱语音合成（SVS）模型的节奏和旋律相似性指标。该工作的实际意义在于为 SVS 系统提供了可扩展、低成本的高质量训练数据标注方案。主要局限性包括：BPM 估计假设单全局节奏可能不适用自由节奏歌曲；自回归解码中歌词前后缀可能不一致；性能受自动标注流程的质量上界约束；以及实验仅在中文数据上进行。

### 🏗️ 模型架构

VocalParse 的整体架构基于一个预训练的大型音频语言模型（LALM，具体为 Qwen3-ASR），其核心是将歌唱转录重构为一个统一的序列生成问题。

完整输入输出流程：
1.  输入：一段歌唱音频波形。
2.  音频处理：音频被输入音频 tokenizer 转换为离散的音频 token 序列（帧率为 12.5 Hz）。
3.  模型解码：模型以音频 token 序列为条件，以自回归方式生成一个目标文本序列。
4.  输出：生成的序列分为两个阶段：
    *   第一阶段（CoT 前缀）：一个纯歌词序列 `𝒲 = [w1, w2, ..., wN]`。
    *   第二阶段（交错序列）：一个结构化的交错歌词-音符序列 `𝒮_{il} = [w1, p1,1, n1,1, ..., w2, p2,1, n2,1, ...]`。其中，每个歌词词 `w_i` 后紧跟其对应的一个或多个音符的离散表示 `p_i,j`（音高，对应 MIDI 音高）和 `n_i,j`（时值，对应特定时值的 token）。整个序列以歌曲级的 `<BPM>` token 结尾。
5.  后处理：将生成的交错序列解析为结构化的乐谱。

主要组件与设计动机：
*   骨干网络（Qwen3-ASR）：选择这个基于 LALM 的模型是因为它具有强大的音频-语义建模能力，并保留了一定的音乐理解能力。
*   交错提示格式：这是架构的核心设计。传统的 SVT 流水线将歌词识别（ALT）和旋律转录（AMT）分开进行，导致音词对齐需要额外步骤。交错提示将歌词词与其音符序列在生成序列中相邻放置，以序列的“位置”直接编码了音词对应关系，实现了真正意义上的端到端统一转录。
*   链式思维（CoT）提示策略：直接让模型生成交错序列会破坏预训练 LALM 所依赖的连续文本上下文，导致性能下降。因此，作者在交错序列前插入了纯歌词序列作为“语义脚手架”。这使得模型的生成过程分解为两步：首先像标准 ASR 一样识别歌词，建立连续的语义上下文；然后在此基础上生成结构化的交错序列。这既利用了预训练模型的能力，又实现了结构化输出。

### 💡 核心创新点

1.  交错音词提示的统一生成范式：提出了一种将歌词词与对应音符序列交错排列的序列格式（公式1和2），用于自回归生成。之前的方法（如 STARS， ROSVOT）要么分开预测歌词和旋律，要么依赖外部歌词作为输入，无法在一个模型内、一次解码中直接输出包含精确音词对应关系的结构化乐谱。该创新通过序列结构直接建模了这种层级关系，实现了真正端到端的统一转录，收益是消除了对齐后处理步骤，并理论上能提供更准确的音词对齐。
2.  链式思维（CoT）提示适配结构化生成：为了调和交错格式与预训练 LALM 的语言建模偏好，提出了 CoT 提示策略（公式5）。之前基于 LALM 的音频理解工作通常直接进行问答或标注，未考虑在生成结构化序列时如何保护语义连贯性。该创新通过先生成纯歌词序列来“唤醒”和利用模型的 ASR 能力，再以此为条件生成交错序列，收益是显著缓解了直接交错生成带来的语义混淆问题（消融实验显示 WER 从 7.18% 降至 3.79%）。
3.  可扩展的数据构建管道 SingCrawl：构建了一个从网络爬取、音频处理到自动标注的完整流水线，用于生成大规模训练数据。之前的歌唱数据集（如 GTSinger， Opencpop）规模小、标注成本高，限制了模型的训练和泛化。SingCrawl 管道利用重新训练的强制对齐模型和 ROSVOT，为爬取的歌曲生成音词对齐的伪标签，收益是提供了约 2000 小时的训练数据，使 VocalParse 能够学习到更丰富的声学和音乐变异。
4.  支持两种灵活推理模式：基于 CoT 架构，模型无需修改即可支持“音频仅”和“音频-歌词联合”两种推理模式。之前模型通常只支持一种输入模式。该创新使 VocalParse 既可以作为一个独立的完整转录器，也可以作为一个由可靠歌词条件化的旋律转录器，收益是增加了应用的灵活性，并允许在已有歌词时进一步提升旋律转录精度。

### 🔬 细节详述

- 训练数据：
    - 数据集名称与来源：使用 SingCrawl 管道从网络爬取并自动标注的数据（约 2000 小时），以及两个公开学术数据集 GTSinger（中文子集） 和 M4Singer（共约 50 小时）。
    - 规模：总计约 2050 小时。
    - 预处理：SingCrawl 数据经过了元数据过滤（语言、风格、音质）、音频切片、人声分离与去混响、质量控制、强制对齐、音符提取、BPM 估计和量化等步骤（详见附录 A）。
    - 数据增强：未提及专门的数据增强技术。数据多样性主要来自大规模爬取。
- 损失函数：未说明具体损失函数名称。根据描述，采用“标准因果语言建模目标”，即对生成序列中的所有 token 进行自回归交叉熵损失优化。
- 训练策略：
    - 优化器：未说明。
    - 学习率调度：使用余弦学习率调度（Cosine schedule），包含 12k 步的预热（warmup）。
    - Batch Size：使用动态批处理（dynamic batching），每个 GPU 的最大批处理 token 数为 18,000，每个 GPU 每批最多 64 个样本。
    - 训练步数：120k 步。
- 关键超参数：
    - 模型大小：基于 Qwen3-ASR 初始化，参数量为 1.7B。
    - 音频 tokenizer 帧率：12.5 Hz。
    - 音高词汇：128 个 `<PITCH>` token（对应标准 MIDI 音高）。
    - 时值词汇：12 个 `<NOTE>` token（从三十二分音符到全音符，含附点，详见表 4）。
- 训练硬件：在 2 块 NVIDIA H100 GPU 上使用分布式数据并行（DDP）训练。
- 训练时长：约 17 小时。
- 推理细节：使用标准的自回归解码（通常是贪心或束搜索，论文未明确指定）。解码过程分为两个阶段（CoT 阶段和交错阶段）。在“音频-歌词联合”模式下，将提供的歌词作为前缀输入。
- 正则化或稳定训练技巧：未提及除动态批处理外的其他正则化技巧。

关键结论： 使用 VocalParse 自动标注的 SingCrawl 数据训练 SVS 模型，能显著提升节奏相似度（BER↓， IOU↑）和旋律相似度（RPA↑），同时保持较好的合成质量（SingMOS， CE， PQ 基本稳定）。这证明了 VocalParse 作为数据标注工具的实际价值。
