### 📌 核心摘要

1.  问题：当前全模态大语言模型（OLLMs）虽然能处理多种模态输入，但其是否真正实现了“模态不变性”推理（即对相同语义内容，无论以何种模态呈现都能给出稳定答案）尚不明确。现有基准测试缺乏对跨模态一致性的系统评估。
2.  方法核心：提出XModBench，一个大规模三模态（文本、图像、音频）基准测试。其核心设计是：基于语义对齐的三元组数据，系统性地对问题的“上下文”和“候选答案”进行模态置换，生成6种配置，以评估模型在感知、空间、时间、语言和外部知识五大任务上的表现。
3.  创新点：相比以往仅关注跨模态问答能力的基准，XModBench首次明确将“跨模态一致性”作为评估核心。其创新体现在：覆盖所有模态组合的系统性设计；引入“模态差异”和“方向不平衡”作为量化一致性的诊断指标；以及在17个子任务上进行大规模、细粒度的评估。
4.  主要实验结果：对多个主流OLLMs（包括闭源的Gemini系列和开源的Qwen2.5-Omni等）进行了评估。结果显示，即使最强的Gemini 2.5 Pro（平均准确率70.6%），在空间和时间推理任务上准确率也低于60%；音频模态是明显短板，当答案从文本变为音频时，性能大幅下降；同时存在方向不平衡，当视觉作为上下文时性能通常低于其作为候选答案时。
    *   关键结果表格（Table 2 摘录）：

| 模型 | 平均准确率 | 各任务族平均准确率（感知/空间/时间/语言/知识） | 标准差 |
| :--- | :---: | :---: | :---: |
| Gemini 2.5 Pro | 70.6 | 75.9/50.1/60.8/76.8/89.3 | 11.7 |
| Qwen2.5-Omni | 58.6 | 75.5/38.4/32.3/74.1/72.8 | 10.1 |
| Human | 91.5 | 91.0/89.7/88.9/93.9/93.9 | 3.0 |

5.  实际意义：XModBench为诊断和改进全模态模型的跨模态对齐能力提供了关键工具。其揭示的弱点（如空间/时间推理、音频理解、方向不平衡）为下一代模型训练（如需要更多交织模态数据）指明了具体方向。
6.  主要局限性：基准本身无法解释模型不一致的根本原因（是数据问题还是架构问题）；评估主要基于多选题格式，可能无法完全反映开放式推理能力；部分任务（如外部知识）的平衡性高度依赖于候选答案的设计。

### 🏗️ 模型架构

本文的核心贡献是提出评估基准XModBench，而非提出一个新的OLLM。因此，其“架构”指的是评估框架的设计。
- 整体流程：该框架基于精心构建的、语义对齐的文本-图像-音频三元组数据。对于每个三元组，通过系统性地分配“上下文”和“候选答案”的模态，生成6种问题配置。
- 主要组件：
    1.  任务族：包含5个主要任务（感知、空间推理、时间推理、语言理解、外部知识）及其下的17个子任务，确保了评估的广度和深度。
    2.  模态平衡设计：对于每个问题，其语义核心不变，但呈现形式（模态）在上下文和候选答案间进行全排列组合（T/A/V），这是评估一致性的关键。
    3.  诊断指标：
        - 任务能力：平均所有模态配置下的准确率，评估模型对某类任务的整体掌握程度。
        - 模态差异：比较相同语义问题在不同模态下的准确率差异（例如，T→A vs T→V），量化模型对不同模态输入的处理能力差距。
        - 方向不平衡：交换上下文和候选答案的模态（例如，V→T vs T→V），检测模型在跨模态“理解”与“生成/匹配”上的能力是否对称。
- 数据流：三元组数据 → 按任务和模态配置生成多选题 → 输入待评估的OLLM → 收集各配置下的准确率 → 计算上述诊断指标 → 分析结果。

### 💡 核心创新点

1.  面向一致性的系统性基准设计：首次提出并实现了一个专门用于评估跨模态一致性的大规模三模态基准。与以往基准（如AVQA、OmniBench）主要评估感知或问答能力不同，XModBench通过模态交换设计，直接聚焦于模型推理的模态不变性。
2.  量化诊断指标：明确提出了“模态差异”和“方向不平衡”两个量化指标，能够将模糊的“模型有偏见”描述转化为可测量、可比较的数值，为模型改进提供了精准的度量衡。
3.  深入的行为模式分析：利用设计的基准，论文深入分析了当前最强模型（如Gemini系列）的失败模式，揭示了它们在空间/时间推理上的普遍弱点、对音频模态的依赖性，以及受训练数据影响的特征（如交织数据减少方向不平衡）。

### 🔬 细节详述

- 训练数据：
    - 来源与构建：三阶段流程。1）跨模态数据收集：整合现有数据集（如VGG-Sound, STARSS23）、模型生成数据（如使用FireRedTTS生成语音）和网络收集数据（如歌手肖像、电影预告片）。2）问题候选生成：使用模板，并利用GPT-5进行语言流畅性优化（不改变语义），为每个三元组生成6种模态配置下的多选题。3）质量控制：先用基础模型进行过滤，再经人工审核和内测修正。
    - 规模：共61,320个问题-答案对（对应10,220个独特三元组实例）。

### 📊 实验结果

论文对12个OLLMs和一个人类基线进行了全面评估。
主要结果（基于Table 2）：
| 模型 | 平均准确率 | 各任务族平均准确率（感知/空间/时间/语言/知识） | 各模态配置标准差 |
| :--- | :---: | :---: | :---: |
| 最强模型 |  |  |  |
| Gemini 2.5 Pro | 70.6 | 75.9/50.1/60.8/76.8/89.3 | 11.7 |
| 强开源模型 |  |  |  |
| Qwen2.5-Omni | 58.6 | 75.5/38.4/32.3/74.1/72.8 | 10.1 |
| EchoInk-R1 | 59.2 | 75.8/36.6/37.1/73.3/75.8 | 11.3 |
| 人类 | 91.5 | 91.0/89.7/88.9/93.9/93.9 | 3.0 |

关键发现与消融/细分结果：
1.  任务难度：空间和时间推理是所有模型的最大挑战（Gemini 2.5 Pro准确率仅50.1和60.8），而感知和语言任务相对容易（超过75%）。
2.  模态差异：音频是最大短板。图4显示，最强模型在涉及音频模态时准确率显著下降（例如，ΔT vs. A 达到 -49）。视觉-文本配置表现最好。
3.  方向不平衡：图5显示，模型普遍存在方向不平衡，尤其是在文本-视觉和音频-文本对之间。例如，Qwen2.5-Omni在V→T（视觉作上下文，文本作答案）比T→V准确率高16.6%。
4.  多模态上下文增益：附录E（Table 3）的初步实验表明，同时提供音频和视觉上下文（A+V→T）相比单模态上下文，能带来有限但一致的性能提升（如Gemini 2.5 Pro提升1.16%），但并非总是叠加。
