### 📌 核心摘要

1.  解决的问题：现有的视频编辑方法大多忽略音视频同步，且缺乏对实例级区域进行精细时空控制的能力。
2.  方法核心：提出AVI-Edit框架，包含三个核心组件：(1) 基于流匹配和预训练视频模型（Wan2.2）的音频同步视频骨干网络，通过逐帧交叉注意力融合音频引导；(2) 粒度感知掩码精炼器，迭代优化用户提供的粗糙掩码为精确的实例掩码；(3) 自反馈音频代理，通过“分离-生成-混合-返工”的流水线，利用现成模型组件稳健生成高质量的编辑引导音频。
3.  创新之处：首次提出“精度因子”来量化并引导掩码的迭代精炼过程；设计了集成多种离散音频模型的自反馈代理，以应对语音与非语音事件的不同处理需求；构建了首个大规模、实例级标注的音视频编辑数据集AVISet。
4.  主要结果：在AVISet和AvED-Bench两个数据集上，AVI-Edit在视觉质量（FVD: 299.19）、音视频同步（Sync-C: 4.15, AC: 26.90%）等关键指标上均显著优于AvED、Ovi等基线方法。消融实验表明，移除任何核心组件（掩码精炼器、精度因子、音频代理）都会导致性能下降。用户研究显示其在音视频同步、文本对齐和整体偏好方面均获最高票。音频代理生成的音频在91%的情况下达到“可接受”或“完美”。
5.  实际意义：为视频内容创作提供了新的可能，如修改说话者语音、改变人物外观、通过声音改变视觉动态等，推动了音视频联合编辑技术的发展。
6.  主要局限：一次只能处理一个目标实例，编辑多实例需串行运行；音频代理依赖外部模型，其性能上限受所集成模型能力约束。

### 🏗️ 模型架构

AVI-Edit 是一个多模块协同的框架，如图2所示，其整体流程是：给定原始视频、一个表示目标实例的粗糙掩码和一段描述编辑方向的文本，模型输出编辑后的视频及其同步音频。

![AVI-Edit 框架图](https://arxiv.org/html/2512.10571v1/x2.png)

1.  音频同步视频骨干网络：
    *   输入：原始视频经VAE编码的潜在码 `z`，粗糙掩码 `m`，文本 `y`，以及由音频代理生成的精炼音频 `a`。
    *   架构：基于预训练的Wan2.2-5B视频扩散Transformer构建。处理流程为：将掩码与潜在码拼接作为视频Token -> 自注意力 -> 多模态交叉注意力（接收文本Token） -> 逐层DiT块。关键改进是在每个DiT块中引入逐帧交叉注意力层，用于接收音频Token `a`，实现音视频在时间维度上的对齐。
    *   训练：采用流匹配（Flow Matching）目标进行训练，公式为 `L_fm`。在推理时，从高斯噪声开始，通过ODE求解器逐步去噪得到编辑后的潜在码。
    *   可选控制：通过一个统一接口支持涂鸦、姿态、参考图等额外控制条件，分别通过元素加法或拼接注入。

2.  粒度感知掩码精炼器：
    *   输入：原始视频Token，粗糙掩码 `m_p`，精度因子 `p`，音频Token `a`。
    *   架构：采用与视频骨干类似的扩散Transformer架构。核心设计是：(a) 用精度因子 `p` 通过自适应层归一化（AdaLN）注入粒度信息（图7）；(b) 用视频Token替代文本Token输入多模态交叉注意力，以便利用视觉语义进行掩码预测；(c) 通过逐帧交叉注意力接收音频Token。
    *   功能：在ODE求解的每一步迭代地精炼掩码。第一步使用初始粗糙掩码和高精度因子 `p`，后续步骤使用上一步精炼的掩码，并根据预定调度降低 `p` 值（实验表明“即时降低”策略最优）。精炼后的掩码用于视频骨干网络的背景保留。

3.  自反馈音频代理：
    *   功能：生成用于引导视频编辑的高质量音频 `a`。
    *   流水线：
        1.  分离与生成规划：使用音频描述器理解原始音频语义，再使用VLM结合视频、掩码、语义和编辑文本，生成分离指令 `c_sep` 和生成指令 `c_gen`。
        2.  模型选择与执行：根据指令从模型库中选择合适的分离模型（针对语音或非语音事件）和生成模型（文本转语音、音乐、音效），分别得到保留成分 `a_sep` 和生成成分 `a_gen`。
        3.  混合与评判：将两者混合。使用MLLM（评判者）从分离准确性、生成准确性、声学和谐度等5个维度打分（总分阈值 `τ=7`）。
        4.  返工循环：若不达标，MLLM生成改进建议反馈给分离和生成模型，重新执行直至达标或达到最大迭代次数。

### 💡 核心创新点

1.  粒度感知掩码精炼器：首次提出“精度因子”概念，用于量化和指导从粗糙掩码（如边界框）到精确实例掩码的迭代优化过程。通过将因子注入Transformer的调制层，并利用视频语义（替换文本）和音频提示进行联合预测，实现了对编辑区域前所未有的精细空间控制。
2.  自反馈音频代理：设计了一个模块化的“分离-生成-混合-评判-返工”流水线，能够稳健地处理语音和非语音两种场景。它不是端到端生成音频，而是灵活组合多种现成模型，并通过MLLM进行质量监控和迭代改进，确保生成的音频既符合编辑指令，又能作为可靠的时间引导信号。
3.  实例级音视频同步编辑框架：将上述创新组件整合到基于流匹配的视频生成骨干中，首次构建了一个端到端的、支持用户交互（粗糙掩码+文本）的实例级音视频同步编辑系统。
4.  大规模实例中心数据集AVISet：构建了一个包含71K训练集、配有精确实例掩码和场景文本的视频数据集，填补了该领域缺乏专用训练和评估数据的空白。

### 🔬 细节详述

- 训练数据：使用新构建的AVISet数据集，包含71K训练、1K验证、1K测试视频片段（每段约10秒，720P 24FPS）。数据来源包括公开数据集（MovieBench, Condensed Movies等）和网络视频。经过严格的视听质量、单实例、非静音等多轮筛选，并使用Grounded-SAM-2标注实例掩码，使用Qwen-VL生成文本描述。
- 损失函数：联合损失 `L = L_fm + λ L_mask`。
    - `L_fm`：流匹配损失，用于训练视频骨干，估计速度场。
    - `L_mask`：基于焦点损失的掩码精炼损失，用于训练GAMR，平衡前景/背景样本。
- 训练策略：
    - 优化器：Adam。
    - 学习率：2e-5。
    - 训练步数：160k步。
    - 硬件：8张 NVIDIA A800 GPU。
    - 初始化：视频骨干和GAMR均从预训练的Wan2.2-5B权重初始化，冻结VAE。
- 关键超参数：
    - 掩码降级参数 `α=0.25`, `γ=2.0`。
    - 联合损失权重 `λ=1.0`。
    - 音频代理评判阈值 `τ=7`（总分10分）。
- 推理细节：
    - 视频生成使用ODE数值求解器。
    - 掩码精炼器在ODE的每一步迭代运行，精度因子 `p` 采用“即时降低”调度：仅第一步用初始值，后续步 `p=1`。
    - 音频代理平均需要1.67次返工迭代，总处理时间约70秒/片段。
