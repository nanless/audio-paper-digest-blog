### 📌 核心摘要

1. 问题：现有长视频理解方法多关注有限长度视频的感知，而缺乏对在线、无限流式多模态输入的处理能力，也难以构建和利用类人的长期记忆来完成需要世界知识和跨模态推理的复杂任务。
2. 方法核心：提出M3-Agent框架，其包含并行工作的记忆化与控制两大过程。记忆化过程持续处理视频流，生成情景记忆和语义记忆，并构建实体中心的长期记忆图；控制过程则根据指令，通过强化学习训练的多轮推理自主检索并利用记忆完成任务。
3. 创新点：与已有方法相比，新在：(1) 模拟人类认知的双类型（情景/语义）记忆生成；(2) 以实体为中心组织记忆，保持身份一致性；(3) 通过强化学习训练多轮迭代检索与推理的控制策略。
4. 实验结果：论文提出了M3-Bench基准（含机器人视角和网络视频子集）。M3-Agent在M3-Bench-robot、M3-Bench-web和VideoMME-long上，分别以6.7%、7.7%和5.3%的准确率优势超过了最强基线（Gemini-GPT4o-Hybrid）。关键结果如下表：

| 方法 | M3-Bench-robot | M3-Bench-web | VideoMME-Long |
| :--- | :---: | :---: | :---: |
| Gemini-GPT4o-Hybrid (最强基线) | 24.0 | 41.2 | 56.5 |
| M3-Agent | 30.7 | 48.9 | 61.8 |

5. 实际意义：推动多模态智能体向具备长期记忆和推理能力的“类人”智能体发展，为家庭机器人、助手等实际应用场景提供了基础框架和评估标准。
6. 主要局限性：记忆生成的质量依赖于底层多模态模型；训练数据为私有数据集；实验场景虽多样，但仍未完全覆盖所有真实世界复杂交互；强化学习训练成本较高。

### 🏗️ 模型架构

M3-Agent的整体架构由记忆化与控制两大并行工作流构成，核心是一个多模态大语言模型（MLLM）与一个外部的长期记忆数据库进行交互。

![M3-Agent系统架构图](/audio-paper-digest-blog/images/iclr-2026/2026-05-04/PMz29A7Muq-0.png)

图1：M3-Agent整体架构。左上为记忆化工作流：MLLM处理环境输入的视频/音频，并利用人脸检测、说话人分离等工具，生成并更新长期记忆（包含情景与语义记忆）。右下为控制工作流：MLLM根据指令，自主进行多轮推理，并通过检索工具从长期记忆中获取相关信息，最终生成回答。长期记忆以实体为中心进行组织。

详细流程：
1.  输入：实时视频流与音频流。
2.  记忆化过程：
    *   工具使用：系统调用面部识别（使用InsightFace库）和说话人识别（使用Gemini-1.5-Pro进行分割与ASR，ERes2NetV2进行语音嵌入聚类）工具，从视频片段中提取人脸ID和声音ID。
    *   记忆生成：MLLM处理30秒的视频片段，结合提取的ID，生成两种记忆：
        *   情景记忆：记录具体事件（如“<face_1>说：‘我早上不喝这个不行。’”）。
        *   语义记忆：提取通用知识（如“<voice_3>的名字是爱丽丝。”、“<face_1>喜欢喝黑咖啡。”），并建立人脸ID与声音ID之间的等价关系。
    *   记忆存储：生成的记忆项被存入长期记忆数据库，形成以实体为中心的图结构。节点代表记忆项（含内容、嵌入向量、置信度权重等），边代表关系。系统通过加权投票机制处理冲突信息。
3.  控制过程：
    *   当接收指令（如问题）时启动。
    *   多轮检索与推理：MLLM（初始化自Qwen3）生成包含推理、动作和参数的响应。
        *   若动作为`[Search]`，则系统调用搜索工具（`search node`或`search clip`）从长期记忆中检索相关信息，并将结果追加到上下文，进入下一轮。
        *   若动作为`[Answer]`，则生成最终答案并终止。
    *   该过程最多执行H轮（实验中设为5），实现了迭代式的、任务聚焦的记忆检索与推理。

关键设计：将记忆生成（依赖多模态理解）与控制推理（依赖强语言模型）解耦，并分别用不同的基础模型（Qwen2.5-Omni与Qwen3）初始化，然后通过监督学习和强化学习（DAPO）进行特化训练。

### 💡 核心创新点

1.  面向长期记忆的智能体框架（M3-Agent）：首次系统性地将“感知-记忆-推理”闭环构建为一个多智能体框架，模拟了人类从实时流中积累并利用世界知识的过程。之前方法多关注有限视频或单一类型记忆。
2.  实体中心的双类型长期记忆：借鉴认知科学，明确区分并生成情景与语义记忆，并以实体为中心（通过ID关联）组织记忆图。这解决了以往方法中身份信息模糊、跨模态信息割裂的问题，提升了长期一致性。
3.  强化学习训练的多轮检索推理控制：将控制过程建模为强化学习问题，训练模型自主决定何时、检索何种记忆，并进行多轮推理。这超越了传统单轮RAG，在复杂问题上实现了更精准的上下文感知检索。
4.  高质量评测基准（M3-Bench）：填补了现有长视频QA基准的空白，专门设计用于评估智能体的长期记忆与推理能力，包含机器人视角和多样化网络视频，问题类型涵盖人物理解、知识提取和跨模态推理。

### 🔬 细节详述

- 训练数据：
    - 记忆化模型（memory-7b-sft）训练数据：私有视频数据集，500个长视频，共26,943个30秒片段。为每个片段合成10,952个记忆生成演示样本（情景记忆、身份映射、语义记忆），使用GPT-4o和Gemini-1.5-Pro混合生成。
    - 控制模型（control-32b-rl）训练环境：使用训练好的记忆化模型（memory-7b-sft）为上述视频生成长期记忆。训练集包含2,736个问答对。
- 损失函数与训练策略：
    - 记忆化：监督微调（SFT），在合成演示数据上训练Qwen2.5-Omni-7b，3个epoch，学习率1e-5，批大小16，使用16个80GB GPU。
    - 控制：使用DAPO强化学习算法（一种针对LLM的优化PPO变体）训练Qwen3-32b。奖励函数为二元奖励：由GPT-4o评估器判断答案是否正确（R=1/0）。优化目标见公式(2)，其优势函数经过标准化处理，并设有特定的裁剪范围和约束（保证平均奖励非全1以避免退化）。
- 关键超参数：
    - 模型大小：记忆化策略基础为7B参数，控制策略基础为32B参数。
    - 控制过程最大轮数H=5。
    - 记忆检索：`search clip`返回最相关的2个片段（top-2）。
    - 文本嵌入：使用OpenAI的`text-embedding-3-large`模型。
- 训练硬件：记忆化训练使用16个80GB GPU；控制训练硬件未详细说明。
- 推理细节：控制过程为自回归生成，解码策略未明确提及，但强化学习训练通常对应特定解码参数（如温度），论文未提供具体值。

### 📊 实验结果

论文在M3-Bench和VideoMME-long上进行了全面评估。

主要对比实验结果：

| 方法类别 | 方法名称 | M3-Bench-robot | M3-Bench-web | VideoMME-Long |
| :--- | :--- | :---: | :---: | :---: |
| Socratic模型 | Qwen2.5-VL-7b | 3.4 | 14.9 | 46.9 |
| | Gemini-1.5-Pro | 8.0 | 23.2 | 38.0 |
| | GPT-4o | 8.5 | 28.7 | 38.8 |
| 在线视频理解 | MA-LMM | 24.4 | 24.3 | 17.3 |
| | Flash-VStream | 19.4 | 23.6 | 25.0 |
| 智能体方法 | Gemini-Agent | 16.9 | 34.1 | 55.1 |
| | Gemini-GPT4o-Hybrid | 24.0 | 41.2 | 56.5 |
| M3-Agent | M3-Agent (ours) | 30.7 | 48.9 | 61.8 |

表4（简化）：主要结果对比。M3-Agent在所有基准上均取得最佳性能。

![不同问题类型性能对比](/audio-paper-digest-blog/images/iclr-2026/2026-05-04/PMz29A7Muq-3.png)

图4：M3-Bench中不同问题类型的比例分布。M3-Bench-robot与M3-Bench-web在问题类型分布上有所不同。

关键发现：
1.  M3-Agent显著优于所有基线，尤其是在需要深度理解和记忆的人物理解（Person Understanding） 和跨模态推理（Cross-modal Reasoning） 类问题上优势明显。例如，在M3-Bench-web上，相比Gemini-GPT4o-Hybrid，其在人物理解上高出15.5%（59.3% vs 43.8%），在跨模态推理上高出6.7%（44.3% vs 37.6%）。
2.  消融实验验证了各组件的重要性：
    *   记忆模型：用SFT训练的记忆模型（memory-7b-sft）优于提示工程（prompt）方法。移除语义记忆会导致性能大幅下降（在M3-Bench-robot上从30.7%降至13.6%），证明了语义记忆对于构建世界知识的关键作用。移除实体ID等价也显著降低性能。
    *   控制模型：
        *   DAPO 强化学习训练（control-32b-rl）显著优于GRPO和单纯的提示工程（control-32b-prompt）。例如，相比提示基线，control-32b-rl在M3-Bench-robot上提升10.0%（30.7% vs 20.7%）。
        *   移除“指令间追加”（inter-turn instruction）或移除推理过程都会导致性能严重下降，证明了多轮迭代检索和显式推理的必要性。
