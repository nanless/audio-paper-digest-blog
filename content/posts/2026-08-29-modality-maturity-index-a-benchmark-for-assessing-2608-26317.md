### 💬 毒舌点评

这篇稿子最值得保留的不是“模型分数很低”这个口号,而是把失败拆成接口是否接收输入、是否交付所需媒介、已交付内容是否正确 3 层。正文把 99.4–100 的 precision 与 14.5–33.8 的 recall 放在同一个解释框架里,因此不会把低分误读为模型随意产生错误媒介。工具实验也被明确限为量规校准,而不是替裸 API 主实验补 1 张总榜。

仍需对结论保持克制:MMI Value 是设计上的主分数,却未在裸 API 主设置充分实测;70.8% 的人机一致率及 0.41 的 Scott’s π 不能证明裁判无偏,且文档工具缺席。读者若拿它做音频或 agent 系统测试,应把它当作输出路由与交付测试,并另外补内容正确性、端到端时延和跨媒介一致性验证。

### 📌 核心摘要

本文提出 MMI,将多输入请求中“是否按要求交付文字、图像、音频、视频或文档”与“交付内容是否正确”拆开测量。893 题主实验显示五家裸 API 的 precision 几乎满分而 recall 很低,当前主要瓶颈是漏交媒介。工具脚手架的人机量规一致率为 70.8%、Scott’s π 为 0.41,但不能替代裸 API 的内容质量主榜。

把 1 张轮胎照片交给所谓 omni 模型,请它标注尺寸;或给出术前语音,请它同时返回文字摘要、鼓励视频和可打印文件。回答 1 段文字并不等于完成请求。本文把这种“输入已理解、输出媒介却没交付”的失败单独变成基准问题:5 种媒介是文字、图像、音频、视频和文档,单个请求最多组合 3 种输入与 3 种输出。

Modality Maturity Index(MMI)不是在问模型能否识别 1 个对象,而是在问它能否按用户指定的媒介组合把东西交到手。它收集 893 个自包含问题,并为每个预期输出媒介配有人写的判分准则。因此,对做语音与多模态系统的人,它更像 1 次输出路由压力测试:音频输入并不自动意味着模型会返还音频,能调用语言模型也不等于能完成跨媒介交付。

把 1 次评测想成 1 张“交付订单”会比把它想成一道问答题更准确。订单有 3 层:用户给出的文字、声音、图片、视频或文件是输入资产;用户真正需要拿到的媒介集合是 gold 输出集合;每种需要交付的媒介又有独立的内容要求。比如 1 段术前语音可以要求文字建议、鼓励视频和可打印文件;模型若只复述语音,可能理解了输入,却没有完成任何 1 个非文字交付。反过来,模型多给 1 张无关图片也不是“更全面”:它改变了返回集合,却没有满足订单中缺失的项目。

这个建模让读者在读后续分数前先做 1 个选择。若你在做 API 路由或产品验收,关心的是每个所需文件、波形或视频是否真的到达;若你在做生成模型,关心的是已经到达的资产能否回答问题。MMI 不把这 2 个问题混成一句“多模态能力”,而是要求先指出失败发生在交付还是内容。这个区分也给出可证伪的判断:如果模型总能返回 gold 集合,MPS 会接近完善;如果它只会描述该生成什么而不交资产,MPS 即使语言流畅也会失败。

既有评测大多测“文字加 1 种感知输入”的理解能力,或把不同生成媒介拆成平行赛道;它们很少要求系统在同一题里选择多个非文字输出。Zhang et al. (2025b) 所代表的跨媒介评测路线覆盖了多种输入,但关系是“扩展理解覆盖并比较不同输入能力”;与本文的差异是本文把输出媒介选择也作为同一请求的判定对象。Zhang et al. (2025a) 所代表的生成评测路线能检查生成侧,但关系是“单媒介生成质量与内容保真”;差异是 MMI 要检查多个输入、多个输出是否被正确组合。

这不是宣传词的差别。若 1 个基准只让模型输出文本,模型无需决定何时交付音频、视频或文档;若 1 个基准只测图像生成,也无法发现模型是否漏掉用户同时索要的文字说明。MMI 的目标是把这层接口行为从模型内容能力中分离出来。

因此,表 1 最值得读的不是某一行是否勾选得更多,而是“输入覆盖”和“输出选择”是否同时出现。理解基准可以让模型读音频或视频后答 1 段文字;单媒介生成基准可以检查 1 张图是否符合提示词;二者都不能回答 1 个更接近系统工程的问题:面对包含多种资产的请求,系统是否决定交付恰当的若干媒介,而不是只把所有事折回文本。对语音研究者,这也避免把“支持音频输入”误写成“支持音频工作流”。

MMI 的核心预测很具体:当请求要求多种输出时,模型的返回集合应当与 gold 集合一致;若只是在任何输入后都输出文字、或只会在单一生成通道中工作,就会在这一测试上暴露。能够推翻这项预测的证据也很明确:在相同请求下,模型应稳定交齐所需媒介,并且不把不需要的媒介当作默认填充。后文的 MPS、precision、recall 和完整通过率各自对应这张预测的不同切面。

每道题先给模型原始输入资产,再规定 gold 输出媒介集合。作者用 2 条互补路径读答案。Modality Presence Score(MPS)是“是否把该交的媒介交出来”的集合 F1:它比较返回集合与预期集合,完全忽略返回资产的内容是否正确。F1 是 precision 与 recall 的平衡量;pass rate 更严格,只有一题中所有预期媒介都出现才算通过。

另 1 条路径是 MMI Value。它让 LLM judge 按每种媒介的准则给内容打分,再先在媒介内、后在题目间做平均;缺少预期媒介直接记零。2 条分数不应互换:MPS 高说明交付媒介对,不能证明内容好;MMI Value 低也可能只是完全没交付可判的资产。本文的主实验正因可判资产太少,主要报告 MPS,而不是把 MMI Value 伪装成已验证的端到端排行榜。

这里有 2 个容易误读的平均。MPS 是逐题比较“返回了什么媒介”和“应该返回什么媒介”的集合 F1,然后再跨题平均;它不是把所有输出文件堆在一起后算 1 个总比例。这样,一道要求 3 个输出的题不会因为可列出更多项目而天然压过只要求 1 个输出的题。MMI Value 也先在同一媒介内平均各条准则,再对该题各个预期媒介的均值做平均,因此 1 段冗长文本不会凭借写了更多句子占用图像或音频的权重。

precision 回答的是“已经交付的媒介有多少本来就该交付”,recall 回答的是“订单要求的媒介有多少确实被交付”,F1 把两者放在一起。pass rate 则比 F1 更像交付验收:只要一项应交媒介缺席,该题就不算完整通过。论文还说明,计算 precision 时不惩罚不需要的文字,因此文字在这里几乎是免费的;这意味着高 precision 不能被读成模型生成了高质量的多媒介资产,它只说明模型很少凭空多交非文字媒介。

把 1 个具体请求放进这套读法就清楚了。若用户要文字、视频和文档,模型只给文字:precision 可以不低,但 recall 只承认已交的一项,pass rate 为失败;若模型给了文字、视频和额外图片,却漏掉文档,recall 和完整通过率仍会提醒读者订单没有完成。若三项媒介都返回了但视频内容答错,MPS 仍可能很高,只有 MMI Value 的内容准则会发现这 1 层。因此研究报告应先说自己在诊断路由、交付还是内容,不能拿 1 个数字替 3 个决策负责。

准则本身也有边界。每条准则被设计成可针对单一输出媒介判断:它应当指出可观察的事实、值或性质,而不能要求裁判从另 1 种输出里补全信息。这样做让音频、图像、视频和文档可以分别评分,但它也主动放弃了跨媒介一致性,例如视频画面是否与音频内容完全对齐。读者若要评价这类系统级一致性,需要在 MMI 之外再增加联合检查,而不应把单媒介内容分数误认为已经覆盖了它。

#### 一道题如何从用户需求走到两种分数

每道题先给模型原始输入资产,再规定 gold 输出媒介集合。作者用两条互补路径读答案。Modality Presence Score(MPS)是“是否把该交的媒介交出来”的集合 F1:它比较返回集合与预期集合,完全忽略返回资产的内容是否正确。F1 是 precision 与 recall 的平衡量;pass rate 更严格,只有一题中所有预期媒介都出现才算通过。

另一条路径是 MMI Value。它让 LLM judge 按每种媒介的准则给内容打分,再先在媒介内、后在题目间做平均;缺少预期媒介直接记零。两条分数不应互换:MPS 高说明交付媒介对,不能证明内容好;MMI Value 低也可能只是完全没交付可判的资产。本文的主实验正因可判资产太少,主要报告 MPS,而不是把 MMI Value 伪装成已验证的端到端排行榜。

这里有两个容易误读的平均。MPS 是逐题比较“返回了什么媒介”和“应该返回什么媒介”的集合 F1,然后再跨题平均;它不是把所有输出文件堆在一起后算一个总比例。这样,一道要求三个输出的题不会因为可列出更多项目而天然压过只要求一个输出的题。MMI Value 也先在同一媒介内平均各条准则,再对该题各个预期媒介的均值做平均,因此一段冗长文本不会凭借写了更多句子占用图像或音频的权重。

precision 回答的是“已经交付的媒介有多少本来就该交付”,recall 回答的是“订单要求的媒介有多少确实被交付”,F1 把两者放在一起。pass rate 则比 F1 更像交付验收:只要一项应交媒介缺席,该题就不算完整通过。论文还说明,计算 precision 时不惩罚不需要的文字,因此文字在这里几乎是免费的;这意味着高 precision 不能被读成模型生成了高质量的多媒介资产,它只说明模型很少凭空多交非文字媒介。

把一个具体请求放进这套读法就清楚了。若用户要文字、视频和文档,模型只给文字:precision 可以不低,但 recall 只承认已交的一项,pass rate 为失败;若模型给了文字、视频和额外图片,却漏掉文档,recall 和完整通过率仍会提醒读者订单没有完成。若三项媒介都返回了但视频内容答错,MPS 仍可能很高,只有 MMI Value 的内容准则会发现这一层。因此研究报告应先说自己在诊断路由、交付还是内容,不能拿一个数字替三个决策负责。

准则本身也有边界。每条准则被设计成可针对单一输出媒介判断:它应当指出可观察的事实、值或性质,而不能要求裁判从另一种输出里补全信息。这样做让音频、图像、视频和文档可以分别评分,但它也主动放弃了跨媒介一致性,例如视频画面是否与音频内容完全对齐。读者若要评价这类系统级一致性,需要在 MMI 之外再增加联合检查,而不应把单媒介内容分数误认为已经覆盖了它。

#### 先问接口承诺,再解释为什么只跑五家裸 API

主实验比较五个提供商 API,使用默认参数、统一 32,768 token 生成上限、最多五次重试,并把无法接受输入的调用记为失败。这里的 API 是提供商直接接口,而非带浏览器、文件转换器或专用生成器的 agent。这样的控制让“是否接收输入”和“接收后是否返回所需媒介”能同时被记录,但也限制了外推:它不报告成本、吞吐、延迟、随机种子,不能代表真实产品工作流。

表中的输入/输出支持矩阵是读主结果的前提。一个模型即便宣称多模态,也可能只接受部分 PDF 或只输出文字;这会在 input failure rate 中显现。表外还应注意:presence 的默认宽松检测允许原生资产、可工作的链接,或后备判断器识别出的正确媒介;它接近用户收到可用资源的情形,却不等于每次都是模型原生生成的像素或波形。

PDF 是 portable document format 的文件形式,本文将其列为可能影响输入接受率的一类文档,而没有把不同 PDF 解析能力简化成单一模型能力分数。

主实验的控制变量也决定了它在测什么。五个被测对象是按提供商直接 API 暴露的模型;其中 Llama 4 Maverick 由作者在本地部署,其余通过各自提供商 API 查询。它们使用默认参数,统一生成上限和重试规则。这样的设计压低了提示工程、浏览器插件、文件转换器和外接生成器带来的混杂,因此所得分数适合回答“裸接口是否完成交付订单”,而不是回答“某个带丰富工具的产品最终能否帮用户完成任务”。

presence 的判定有三条路径:直接返回的资产算原生交付;返回指向正确媒介资产的链接也可被识别;前两条未识别时,再由后备 judge 判断回答里是否真的给出了该媒介。默认使用宽松口径,是因为对某些用户来说可用的视频链接确实完成了请求。代价是它不能等同于原生生成能力:链接、后备判断和模型直接渲染像素或波形是不同的系统行为。要研究底层生成接口,读者应使用严格口径,只把原生返回资产计为出现。

后备检测也不是把“谈论媒介”当成“交付媒介”。检测说明明确排除“我不能生成图片”之类的拒答,也排除仅描述图片、给出视频脚本或写歌词来代替音频。它寻找的是实际媒体数据、对应文件内容或可用资产链接。复现时若改变这一判断规则,MPS 的变化可能来自检测器而非模型;因此检测来源必须和模型响应一起保存,尤其不能把链接失效后再补出的网页内容算回原调用的成果。

#### 五家 API 的关键失败不是乱给媒介,而是漏交媒介

表 4 比较的单位是同一 893 题设置下各模型的样本平均。GPT-5.4 的 MPS/F1 为 34.9,召回为 33.8,pass rate 为 31.0;Claude Opus 4.6 相应为 15.6、14.5 与 11.3。所有模型 precision 在 99.4 到 100 之间,说明它们很少额外交付错误媒介;真正拉低 F1 的是 recall 仅 14.5 到 33.8,也就是该交的媒介没交出来。

这张表还给出 input failure rate:Gemini 3.1 Pro 为 8.0%,Claude Opus 4.6 为 37.0%。把它与 recall 一起看,才能区分“请求根本进不去”和“进去了却只交文字/部分媒介”两类失败。最高 pass rate 也只有 31.0,进一步说明单题的部分完成比完整完成更常见。该证据支持的是裸 API 快照中的交付瓶颈,不是五个模型的内容能力总排名。

一条实用的诊断路径是先看 input failure rate,再看 recall,最后看 pass rate。输入失败高时,首要问题是接口是否接受给定的音频、视频、文档或其他资产;这一步失败的请求被记为零,因此不能把它误诊为“模型看懂了但故意没生成”。输入能进入而 recall 仍低时,才更接近输出路由或媒介交付缺口。若 recall 尚可但 pass rate 明显更低,则说明模型常完成订单的一部分,却没有把所有必要项一起交齐。

precision 接近满分会使这条路径更有辨识度。它排除了一个看似合理但并不符合表 4 的解释:低 F1 主要是模型杂乱地返回无关媒介。本文的证据更符合另一种模式——模型大多没有多交错误非文字媒介,却经常不交所需媒介。这个区别会改变工程处方:前者需要抑制错误工具或媒介选择,后者需要改进能力暴露、工具路由或交付协议。两者都不能只靠更漂亮的文本回答修复。

不过,不能从平均表直接推导某一媒介在所有条件下最难。论文按媒介的分析指出,很多非文字交付的分数反映的是模型是否能够返回该媒介,而非纯粹的内容难度;图像和视频有时来自链接,GPT-5.4 的部分文档信用则主要来自后备检测。音频在此设置下尤其值得单列,因为所有被测模型都不把它作为输出支持,且没有模型返回音频链接。它说明当前接口栈的缺口,却不等于任何带专用音频工具的产品都会同样失败。

GPT-5 是表中 GPT 系列模型名称的共同前缀,GPT 是 generative pre-trained transformer 的简称;这里使用它们只是识别被评测 API,不把提供商命名当成能力证据。

#### 工具脚手架能让内容量规接受一次更公平的检验吗

主实验返回的资产太少,作者另设三模型工具脚手架:模型可调用 image_gen、audio_gen、video_gen 三种通用函数,再由后端返回资产;每题最多三轮。这一实验目的不是重排五家 API,而是产生足够资产,让人类与 LLM judge 都能实际按量规检查内容。

在 1,499 个双方都有判断的(题目、模型、媒介)三元组上,总体一致率是 70.8%,Scott’s π 为 0.41;图像是一致率 66.5%、π 为 0.28,音频为 73.6%、π 为 0.45,视频为 74.4%、π 为 0.31。Scott’s π 会扣除机会一致,因此 0.41 不是“裁判已经无偏”的证明。作者也指出 judge 属于 Gemini 家族,不能排除自偏好;开放请求存在多种可接受答案,且文档没有生成工具,所以文档量规在此实验中没有被验证。

这套脚手架的作用不是简单地给模型“加分”。三个调用模型只看到名称分别指向图像、音频和视频的通用函数,以及同样简短、没有后端能力暗示的描述;它们不知道实际后台生成器,也不知道应该怎样针对某个后台优化提示。模型发出调用后,系统返回生成资产,再让模型继续,最多三轮并在不再请求工具时提前停止。这样做的意图是让足够多的媒介资产出现,以便检验内容量规能否工作,而不是替五个裸 API 的主结果构造一个更好的产品配置。

人类与 judge 的比较也不是两位评分者拿同一张完整答卷做同一种判断。人类对每个所需媒介给二元正确或错误判断,并且不看量规;LLM judge 则一次只接收一个媒介的产物和一条对应准则,在多个准则上给分,随后为了对齐人类判断再收紧为二元结果。这样的对齐让一致率有明确含义:它检验按准则拆分的自动判定能否近似无量规的人类结论;它不证明 judge 已经理解了整份跨媒介回答,更不证明量规没有偏差。

因此,70.8% 和 π 的读法应当是“有限校准”而不是“自动内容评估已经可靠”。π 会把双方仅因类别分布而碰巧一致的部分扣除;这里的较低值提示开放式请求、准则表述和裁判错误仍会造成分歧。论文还指出 judge 属于 Gemini 家族且会给该家族产物评分,存在自偏好可能。若要把这一流程用于新的模型比较,应额外保留按媒介的分歧样本、做跨家族裁判复核,并让人类标注协议与 judge 输入范围保持可比。

#### 有工具时的 MMI Value 仍不能和主榜混在一起

工具实验的 Table 5 报告内容型 MMI Value。Gemini 3.5 Flash 的总分为 0.51、去掉文档后为 0.63;Claude Opus 4.8 为 0.36/0.44,GPT-5.4 为 0.29/0.35。文档列全为 0.00,不是模型都被证明不会写文档,而是该实验没有提供文档生成工具。

因此这张表的用途很窄:它证明准则在已生成的资产上可与无量规人类得到有限一致,而不证明裸 API 主实验的内容质量,也不支持把这三行与表 4 的 MPS 排名拼成一个总榜。对于系统研究者,最有价值的结论是先测路由与交付,再在有足够可判资产时测内容;两层失败要分别定位。

读表时还要记住 MMI Value 的聚合顺序。All 是先在每道题的各个预期媒介内汇总准则,再在题内媒介之间平均,最后跨题平均;Excl. doc. 只在仍保留至少一个非文档输出媒介的题上移除文档准则。各媒介列覆盖的题目组合不同,所以它们不会相加或简单平均回 All。把某一列的高低当作一场统一条件下的横向能力赛,会把不同题目分布与工具可用性混在一起。

文档列为零尤其是一个协议负结果,而不是模型写作能力的判决。脚手架只提供图像、音频和视频工具,没有文档生成工具,因而没有生成文档资产供量规检查。这个缺口也提醒复现者:如果新增文档工具,得到的是一个新的工具配置,需要重新报告它与原设置的差异;不能把新分数悄悄接在现有表格后面,再宣称原文已经比较过它。

#### 复跑这个基准前,先决定你想诊断哪一种失败

若目标是接口回归,最小复跑单位是题目、输入资产、预期输出媒介集合和 presence 检测规则;要同时保存原生资产、链接与后备检测来源,避免把“链接交付”和“原生生成”混为一谈。若目标是内容评估,则还需要每媒介准则、judge 版本、人类标注协议以及按媒介分开的失败样本。

论文说明代码与数据集入口已公开,但现有材料没有在本文证据中确认许可证、依赖锁定、供应商版本、完整失败日志、成本或吞吐配置。实践上可把 MMI 接进 agent 的回归测试;研究上则应补直接的检测路由消融、文档工具、跨媒介一致性检查,以及跨时间的 API 版本记录。

一个可执行的最小复跑顺序是:先固定题目、输入资产与每题 gold 输出集合;再对每个模型保留原始 API 响应、重试后的最终状态以及输入是否被拒绝;随后分别记录原生资产、链接和后备 judge 三种 presence 来源。完成这一层后,才能逐题计算集合层面的 precision、recall、F1 和完整通过,并把输入失败从输出漏交中单独列出。若目标是复现 MMI Value,还需要逐媒介准则、每条准则的 judge 输入、模型产物附件和汇总方式;只保存最终分数无法定位争议来自缺失资产、内容错误还是评分规则。

复现者还应把“严格”和“宽松”检测并排报告,而不是先挑一个有利口径。严格结果更接近模型直接交付了什么,宽松结果更接近用户最终获得了什么资源;两者的差距正是链接和后备判断在系统中承担了多少工作。对于视频编辑、音频生成或文件转换等必须产生新资产的任务,链接未必是合格替代;对于寻找既有访谈视频之类的任务,链接又可能恰是正确交付。gold 集合与检测规则必须一起解释,不能脱离用户意图机械套用。

对部署者,本文提供的是回归测试框架而不是上线承诺。它没有报告成本、吞吐、时延、随机种子、完整失败日志或长期 API 版本漂移,也没有直接测跨媒介内容一致性。因而合理的下一步不是把 MPS 当作产品 KPI 的全部,而是在自己的真实工作流中增加端到端时延、失败恢复、权限与安全、资产可用性和用户可接受性的测量,并明确这些扩展不再与本文裸 API 快照完全同条件。

#### 结论应收紧到“输出路由仍未成熟”

MMI 的新意在于把“正确的媒介是否出现”与“出现的内容是否正确”分开。893 题、五种媒介和最多三种输入/输出组合,使它比单媒介问答更接近用户实际提出的多媒介请求。主实验的最强信号不是某个模型领先,而是 precision 接近 100、recall 很低:当前裸 API 更常漏交,而非错误地多交。

不过,主指标 MMI Value 尚未在同一裸 API 设置中充分运行,工具实验中的 70.8% 一致率和 π=0.41 也只是有限的量规校准。它适合被当作输出路由测试与长期追踪工具;在宣称端到端内容能力、产品可用性或跨媒介一致性之前,还缺少直接证据。

读完本文,最应留下的不是一张模型名次表,而是五个可复用的判断。第一,先把用户需要的媒介集合写清,再谈回答是否完成;第二,区分接口拒绝输入、接受后漏交和已经交付但内容错误;第三,高 precision 并不能抵消低 recall,完整交付仍要看 pass rate;第四,工具脚手架可以检验内容量规,却不能替代裸 API 的主比较;第五,链接、原生资产与后备检测应当被分别记录。沿着这五步,研究者可以把“模型看起来很能聊”的印象转换为可定位、可复跑、也可被下一次模型更新推翻的交付假设。
