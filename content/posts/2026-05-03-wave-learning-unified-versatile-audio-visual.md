### 💡 毒舌点评

WAVE 确实是第一个将音频模态无缝纳入 LLM 嵌入框架的“正经”工作，其双音频编码器（语音+音频事件）和分层特征融合的设计既巧妙又实用，解决了 LLM 处理非语音音频的短板。不过，作为一篇强调“统一”的论文，其对“统一”的论证似乎更侧重于检索性能的提升，而对不同模态在共享空间中的语义对齐机制、以及模型在更广泛音频任务（如音频生成、编辑）上的“多功能性”验证略显不足，消融实验可以更深入地剖析模块贡献。

### 📌 核心摘要

1.  要解决的问题：现有基于多模态大语言模型（MLLM）的嵌入工作主要关注图像和文本，对于动态的音频和视频模态探索不足，未能建立一个真正统一、多功能的文本-音频-视频嵌入空间。
2.  方法核心：提出WAVE，一个基于Qwen2.5-Omni的7B参数MLLM嵌入模型。其核心架构包括：a）双音频编码器：使用语音编码器（来自Whisper）和额外的BEATs音频事件编码器来全面捕捉音频信号；b）分层特征融合：聚合LLM多个层最后输出令牌的隐藏状态，通过一个MLP模块生成最终嵌入，以捕获从低级感知到高级语义的信息；c）联合多模态多任务训练：在文本-视频、文本-音频、视频-音频检索和视频问答任务上进行联合训练，使用对称InfoNCE损失和QA任务损失。
3.  与已有方法相比新在哪里：是首个能为文本、音频、静音视频和同步音视频输入生成统一嵌入的LLM基模型。与先前仅处理图像-文本的LLM嵌入模型（如VLM2Vec）不同，WAVE实现了真正的音视频统一。其双编码器设计专门强化了对非语音音频的理解，分层融合策略则比传统的单层最后令牌池化更能利用LLM的深层信息。
4.  主要实验结果：
    - 在MMEB-v2视频基准（包括分类、QA、检索、时刻检索）上，WAVE（总体59.9%）超越了所有开源模型和工业级Seed-1.6-Embedding（55.3%），取得SOTA。
    - 在视频检索任务（如MSR-VTT）和音频-视频检索任务（如VGGSound）上，显著优于基于分离编码器的基线模型。
    - 在音频问答（MMAU, MMAR）上，WAVE（76.6%, 68.1%）甚至超越了其基座模型Qwen2.5-Omni（71.5%, 56.7%），展示了跨模态迁移能力。
    - 消融实验证实：联合训练优于在单一模态对上单独训练；所有层特征MLP融合优于单层池化。

    | :--- | :---: | :---: | :---: | :---: |
    | WAVE 7B | 59.9 | 44.2 | 25.0 | 76.6 |
    | Seed-1.6-Embedding | 55.3 | - | - | - |
    | 参考模型 (Mei et al.) | - | 42.2 | - | - |
    | Qwen2.5-Omni 7B (基座) | - | - | - | 71.5 |
5.  实际意义：为跨模态、任何到任何的应用（如多模态搜索、推荐、问答）建立了一个强大的统一嵌入基线。其生成的提示感知嵌入能力，使得同一个模型可以根据不同指令提取任务相关的表示，极大提升了模型的通用性和实用性。
6.  主要局限性：a) 尽管名为“多功能”，但评估主要集中在检索和问答，对其他音频任务（如生成、增强）的“多功能性”未加验证。b) 双音频编码器的对齐和融合机制可以更优雅地整合进LLM内部，而非简单的输入拼接。c) 论文指出图像数据有助于性能，但未提供完整的训练数据细节。

### 🏗️ 模型架构

WAVE的整体架构是一个端到端的多模态嵌入模型，设计用于处理四种输入模态（文本、视频、音频、音视频）并生成统一的向量表示。

输入输出流程：
1.  输入：模型接收纯文本、视频帧序列、音频波形，或同步的音频-视频对。所有非文本输入都伴随一个文本提示（prompt）。
2.  编码：
    - 文本：使用LLM（Qwen2.5-Omni）的嵌入层进行令牌化。
    - 视频：通过一个预训练的视觉编码器提取视觉令牌。
    - 音频：采用双编码器架构。一个语音编码器（初始化自Qwen2.5-Omni的语音编码器）提取语音相关令牌；一个音频事件编码器（使用BEATs）及其可训练的对齐器提取环境声相关令牌。两者输出频率相同，令牌按时间对齐。
3.  令牌交错：根据输入模态组合，将不同来源的令牌交错拼接成一个输入序列。例如，音视频输入中，视觉和听觉令牌按帧分段交错。文本提示令牌始终附加在序列末尾。
4.  LLM处理：交错后的令牌序列输入到28层的LLM主干网络。模型采用时间对齐的多模态旋转位置编码来保持精确的时序对齐。
5.  嵌入生成：
    - 文本输入：采用标准的最后令牌池化，即取LLM最后一层对应EOS令牌的隐藏状态作为文本嵌入。
    - 多模态输入：采用分层特征融合。聚合LLM所有28层最后输出令牌的隐藏状态，将它们拼接后输入一个轻量级的融合模块（一个两层的MLP，使用GELU激活函数），压缩并生成最终的多模态嵌入向量。
6.  输出：一个固定维度的嵌入向量，可用于下游的分类、检索或问答任务。

关键设计选择及动机：
- 双音频编码器：动机是弥补基础模型中基于Whisper的语音编码器对非语音音频事件理解不足的缺陷。BEATs编码器专门用于音频事件，两者互补以全面捕捉音频信息。
- 分层特征融合：动机是认识到LLM不同层捕获不同层次的信息（低级感知线索到高级语义推理）。通过融合所有层的信息，而非仅用最后一层，可以获得更全面、稳健的表示。
- 交错输入策略：旨在让LLM能够自然地处理交织的、时序对齐的多模态信息。

### 💡 核心创新点

1.  首个统一音视频嵌入的LLM：
    - 局限：此前基于LLM的嵌入模型主要针对图像-文本，音频模态通常被忽略或作为独立分支处理。
    - 如何起作用：WAVE通过精心设计的双音频编码器和交错输入策略，将音频（语音+环境声）与视频、文本对齐到同一个LLM处理流程中，最终投影到共享的语义空间。
    - 收益：实现了真正的任意模态（文本、音频、视频、音视频）间交叉检索，并在多个基准上取得SOTA性能。

2.  分层特征融合策略：
    - 局限：传统方法仅使用LLM最后一层的最后令牌（EOS）作为嵌入，丢失了中间层的丰富信息。
    - 如何起作用：聚合LLM所有层最后令牌的隐藏状态，并通过一个轻量级MLP进行学习式融合，以整合不同抽象层次的特征。
    - 收益：在视频检索等任务上，该方法一致优于仅使用单层（首层、中层或末层）的池化策略，提升了嵌入的表达能力。

3.  联合多模态多任务训练与提示感知嵌入：
    - 局限：分离训练的单模态模型缺乏跨模态知识迁移；传统嵌入模型生成的是任务无关的固定表示。
    - 如何起作用：a）联合训练：在多种跨模态任务（视频-文本检索、视频QA、音频-文本检索、视频-音频检索）上同时训练，促进正迁移。b）提示感知：利用LLM的指令遵循能力，在推理时将特定任务的问题作为提示，生成条件化的嵌入。
    - 收益：a）联合训练在消融研究中显示出跨模态性能提升。b）在视频QA任务中，使用具体问题作为提示的性能（平均72.5%）远高于使用通用提示（平均51.8%），凸显了提示感知的巨大价值。

### 🔬 细节详述

- 训练数据：
    - 规模：总计约490万训练样本。
    - 数据集与来源：
        - 视频-文本检索：Panda-70M (1M视频，使用InternVL-2.5重新标注)、MSVD (24K)、DiDeMo (8K)、ActivityNet Captions (10K)、MSR-VTT (180K)、VATEX (260K)、YouCook2 (10K)、Shot2Story (530K)。
        - 视频QA：LLaVA-Video-178k (100K)。
        - 音频-视频检索：AudioSet (1.7M)、VGGSound (182K)。
        - 音频-文本检索：AudioCaps (49K)、AudioSet-SL (108K)、Clotho (19K)。
    - 预处理与增强：视频采样率2帧/秒，最大128帧，最大分辨率176400像素。音频重采样至16kHz。为增强文本多样性，对拥有多个描述的视频构建样本对。

- 损失函数：
    - 检索任务：使用对称的InfoNCE损失。对于一批N个样本，计算源->目标和目标->源两个方向的交叉熵损失并取平均（公式1-3）。
    - 问答任务：使用对比损失。对于一个问题，计算正确答案嵌入与多个错误答案嵌入的交叉熵损失（公式4-5）。总损失为批次平均。
    - 温度参数：统一设置为τ=0.01。

- 训练策略：
    - 两阶段训练：
        1.  预训练阶段：仅训练BEATs编码器的对齐器（一个两层MLP），使LLM能理解BEATs特征。使用WavCaps、AudioCaps、Clotho数据集，训练3个epoch，在128张H20 GPU上进行。
        2.  主训练阶段：训练视觉编码器的对齐器和LLM主干上的LoRA模块。使用表1中的所有多模态数据，训练1个epoch，在192张H20 GPU上进行，总时长约36小时。
    - 优化器与学习率：学习率为2e-5。
    - 批次大小：每设备batch size为1，总批次大小为192。
    - 正则化：LoRA模块的dropout率为0.05。

- 关键超参数：
    - 模型大小：基于7B参数的Qwen2.5-Omni。
    - LoRA配置：秩128，缩放因子2.0。
    - 音频事件编码器：BEATs编码器 + 两层MLP对齐器。
    - 融合模块：两层MLP，使用GELU激活。
    - LLM层数：28层。

- 训练硬件：192块NVIDIA H20 GPU。

- 推理细节：
    - 检索任务：使用固定提示“Please describe the video/audio”生成嵌入，通过余弦相似度进行匹配。
    - 问答任务：使用具体问题作为提示生成条件嵌入，与各选项文本嵌入计算相似度，选择最相似的选项作为预测答案。

- 其他：数据采样器确保每个mini-batch中的样本来自相同的任务类型和数据源。
